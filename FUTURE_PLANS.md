# Будущие планы и идеи (Roadmap)

В этом файле хранятся идеи для будущих доработок и улучшения приложения Lerne.

---

## 📌 Очередность этапов разработки (Prioritized Roadmap)

### 🔹 Этап 1: Умная синхронизация (Smart Sync) — *Первоочередная задача*
*Подробный технический план в [SMART_SYNC_PLAN.md](file:///c:/121/Lerne_projekt/tma/SMART_SYNC_PLAN.md)*
- **Цель**: Надежное объединение данных между устройствами пользователей и облаком Supabase без потери данных.
- **Ключевые фичи**:
  - Инкрементальная синхронизация по хешам/контрольным суммам и `updated_at`.
  - Умное разрешение конфликтов (приоритет медиафайлов и данных ИИ).
  - Мягкое удаление (`is_deleted = True`) с возможностью восстановления.

### 🔹 Этап 2: Расширенная генерация ИИ (Smart AI & Failover) — *Вторая задача*
- **Цель**: Бесперебойная генерация карточек и расширенные возможности создания контента.
- **Ключевые фичи**:
  - **Failover / Fallback**: Автоматическое переключение на резервные провайдеры (Groq / OpenRouter), если Gemini недоступен или исчерпан лимит (HTTP 429).
  - **Batch AI Generation**: Генерация группы из 20–50 карточек за один клик по списку слов или тексту.
  - **Smart Prompting**: Настройка стиля карточек (разговорные фразы, упор на грамматику, экзаменационные словаря).

### 🔹 Этап 3: Совместная работа над колодами (Collaborative Decks) — *Третья задача*
- **Цель**: Совместное редактирование колод несколькими пользователями с независимым SRS-обучением у каждого.
- **Ключевые фичи**:
  - Разделение: контент карточек `TMA_Card` общий, а `TMAProgress` индивидуален по `(user_id, card_id)`.
  - Таблица участников `TMA_Deck_Member(deck_id, user_id, role, joined_at)`.
  - Выбор при шеринге: «Скопировать себе» (дубликат) или «Присоединиться к колоде» (совместный доступ).
  - Поэтапное внедрение: Level 1 (MVP инвайт и sync), Level 2 (роли и уведомления), Level 3 (real-time).

### 1. Автопереключение провайдеров (Failover)
**Идея**: Если основной провайдер (например, Gemini) выдает ошибку (лимит запросов, сбой сервера), приложение автоматически пробует отправить запрос через резервного провайдера (Groq или OpenRouter).

**Детали реализации**:
- Добавить переключатель **"Автопереключение провайдеров"** в настройках ИИ.
- Реализовать логику "fallback" в `ai_service.py`: если один клиент вернул `success=False`, пробовать следующий по списку, для которого настроен API ключ.
- Уведомлять пользователя через тост: *"Gemini недоступен, переключаюсь на Groq..."*.

### 2. Улучшение генерации (Smart Prompting)
- Добавить выбор «стиля» карточек: краткий, подробный, с упором на грамматику или на разговорные фразы.
- Поддержка генерации сразу группы карточек (Batch AI) по списку слов.

## 📊 Обучение и алгоритмы
- Тонкая настройка интервалов для опытных пользователей.
- Режим «Марафон» (интенсивное повторение слабых мест).
- **Менеджер дубликатов**: Специальный экран для массового удаления или слияния похожих карточек.
- **Умное слияние**: Автоматическое предложение объединить две похожие карточки, сохранив лучшие медиафайлы (картинку от одной, аудио от другой).

## 🃏 Обмен контентом
- **Прямая передача (P2P)**: Возможность отправить карточку другому пользователю напрямую внутри TMA, если он онлайн, минуя бота.
- **Публичные колоды**: Возможность сделать свою колоду публичной для поиска другими пользователями (глобальный поиск).
- **Коллективная работа (Совместные колоды)**: Совместное редактирование колод несколькими пользователями с независимым обучением у каждого.
  - **Архитектура**: 
    - Таблица участников `TMA_Deck_Member(deck_id, user_id, role, joined_at)`.
    - Контент карточек (`TMA_Card`) общий для всех участников, а прогресс повторений (`TMAProgress`) у каждого пользователя свой по ключу `(user_id, card_id)`.
    - Изменения карточек подтягиваются по `updated_at` (Periodic Sync / Sync on Open).
  - **Варианты шеринга**:
    - *Скопировать себе* (автономный дубликат).
    - *Совместный доступ* (присоединение к оригиналу колоды).
  - **Этапы внедрения**:
    - **Level 1 (MVP)**: Таблица участников, синхронизация изменений по `updated_at`, совместное добавление/редактирование.
    - **Level 2**: Права доступа (`owner`, `editor`, `viewer`), история изменений, уведомления в бота о новых карточках.
    - **Level 3 (Продвинутый)**: Supabase Realtime / WebSockets для синхронного отображения правок онлайн.

## 🛠 Технический бэкенд и отладка
- **Система логгирования в БД**: Поскольку Vercel имеет эфемерную файловую систему, нам нужно сохранять логи ошибок и событий в базу данных (таблица `TMALog`). Это позволит анализировать сбои пользователей в реальном времени.
- **Сбор клиентских ошибок**: Эндпоинт для приема логов с фронтенда (React), чтобы видеть ошибки, возникающие прямо на устройствах пользователей.
- **Метаданные логов**: Автоматическое сохранение информации об устройстве (User-Agent), версии приложения и ID пользователя при возникновении ошибок.
