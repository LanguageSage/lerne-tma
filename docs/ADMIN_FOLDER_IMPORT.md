# Локальный импорт колод и медиа

Вкладка **Автор уроков → Публикация → Добавить колоды из папки**. Консоль предназначена для Windows, ПК и ноутбуков; минимальная ширина нового рабочего блока — 1024 px. Код находится только в `tools/admin/`; `.vercelignore` исключает его из публикации. ZIP не поддерживается по условию задачи.

## Использование

1. Выберите локальную папку, включая папку синхронизации Google Диска. Это обычный выбор файлов браузером, без подключения к аккаунту Drive.
2. Отметьте нужные файлы TXT, MD, TEXT или JSON V2; доступны «Выбрать все» и «Снять выбор». Файл с несколькими колодами выбирается целиком.
3. Используйте прежний выбор целевой папки либо создание новой. В режиме «Добавить изображения и аудио» нужна существующая папка.
4. Нажмите «Проверить выбранные колоды». На сервер передаются только выбранные документы, связанные манифесты и явно указанные ими медиа. Проверка не пишет в БД и Storage.
5. Проверьте создаваемые/существующие карточки, назначения файлов, дубликаты, ошибки и конфликты. При необходимости выберите карточку вручную или пропустите строку. Для занятого медиа-поля выберите «Оставить», «Заменить» либо «Пропустить», затем повторите проверку.
6. Нажмите «Подтвердить импорт». Изменение выбора, назначения или цели требует нового предпросмотра. После потери ответа можно повторить подтверждение с прежним request_id; автоматических повторов нет.

Старый импорт отдельных файлов/вставленного текста не менялся. Возврат к нему — «Обычные файлы / текст».

## Манифест версии 1

Имена папок произвольны. Связь определяется `deck_file`, а не совпадением названий папок. Пример `D01_Медиа/media_manifest.json` рядом с `D01_Основы.json`:

```json
{
  "schema_version": 1,
  "deck_file": "../D01_Основы.json",
  "bindings": [
    {
      "card_number": 1,
      "image": "images/shared.png",
      "audio_front": "audio/front.mp3",
      "audio_back": "audio/back.wav"
    },
    {
      "card_number": 2,
      "image": "images/shared.png"
    }
  ],
  "study_audio": [
    {"file": "audio/exercise.ogg", "title": "Послушайте и повторите"}
  ]
}
```

- Пути относительны к манифесту, с `/`; `../` допустим внутри выбранной папки. Абсолютные пути, диски Windows, обратный слеш и выход за корень отклоняются. Файлы по путям сервера никогда не читаются.
- `card_number` — номер строки карточки в проекции **выбранного документа**, с 1. Это позиция для сопоставления с исходным файлом, не авторский идентификатор.
- Необязательный `card_id` в binding — уже существующий числовой ID карточки БД. Он обязан принадлежать целевой колоде и не противоречить `::card_id` исходного документа. Неизвестный/чужой ID нельзя автоматически заменить новым.
- Одно медиа можно указать для нескольких карточек. Два назначения одного поля одной карточки запрещены.
- `image`, `audio_front`, `audio_back` записываются только в `image_path`, `audio_path`, `audio_back_path`.
- `study_audio` добавляется в существующий `deck.metadata.resources` как `type: audio`, с сохранением остальных метаданных. Для многоколодного документа укажите в каждой записи `deck_name`. Повторный URL не добавляется второй раз.
- Без манифеста колода импортируется без локальных медиа; имена файлов не используются для угадывания связей. Нечитаемые манифесты отмечаются предупреждением в интерфейсе; их медиа недоступны до исправления и повторного выбора папки. Ошибки выбранного валидного JSON-манифеста и отсутствующие файлы блокируют применение.

## Идентификация, авторство и права

Используется существующий `::card_id` канонического экспорта. Повтор уже выполненного импорта также узнаётся по квитанции `TMAOfflineBatch`, содержащей полученные при обычном создании ID. Новых `author_card_id`, колонок или таблиц нет.

При первом импорте в существующую колоду у строки без ID/квитанции нет автоматического сопоставления по тексту или позиции. Нужно вручную выбрать существующую карточку; в режиме импорта также можно явно подтвердить создание новой. Изменившийся документ без прежних ID может потребовать нового ручного сопоставления. Несколько колод с одинаковым названием в одной цели блокируют импорт.

Создание выполняют прежние `create_folder`, `create_deck`, `bulk_save_cards`, определение действующего пользователя — `author_service.get_effective_user_id`. Авторство новых объектов присваивается по прежним правилам. UPDATE существующих карточек содержит исключительно медиа-поля и `updated_at`, без сохранения всей модели. Текст, ответы, context, metadata карточки, creator_id, владельцы, история, SRS и прогресс не меняются. Паспорта применяются только при создании новой колоды.

Все серверные проверки проходят существующие collaborative permissions. Импорт требует записи в папку/колоду; изображение — записи в колоду; озвучка — `can_edit_audio` (включая существующий явный grant viewer). Учебные аудиоресурсы требуют права изменять metadata колоды. Права повторно проверяются после загрузки и перед транзакцией привязок. Локальный HTTP perimeter админки сохранён; это доверенная локальная консоль, а не новая пользовательская аутентификация.

## Хранение и ограничения

- До 100 выбранных документов, 500 файлов, 5000 карточек и 100 МБ файлов за пакет. Документ — до 10 МБ, манифест — до 1 МБ, медиа — до 20 МБ. Ограничение HTTP-body действует также для chunked uploads.
- PNG/JPEG/WebP/GIF проверяются Pillow, максимум 25 млн пикселей. Прежний `optimize_image` готовит WebP, максимум 1600 px по стороне и 2 МБ. Анимированный GIF превращается в статическое изображение.
- Аудио не перекодируется: MP3, WAV, OGG, FLAC, M4A проверяются по формату/сигнатуре; у MP3 проверяется заголовок кадра, у PCM WAV — целостность объявленных кадров. Полное декодирование всех кодеков не выполняется.
- SHA-256 исходных и подготовленных байтов виден в API-предпросмотре. Ключи `import_<sha256>.<ext>` неизменяемы. `TMAMedia` — прежний каталог, Storage использует прежние бакеты `images` и `audio`. Совпавшие ключи переиспользуются без скачивания BLOB или Storage GET.
- В обычном/Supabase режиме для аудио нужны `SUPABASE_URL`/`SUPABASE_KEY`: существующий учебный плеер использует CDN audio. Изображения без Storage могут сохраняться в `TMAMedia`. В `LERNE_MODE=LOCAL` Storage не используется: изображения и аудио записываются в LOCAL media root, каталог — в `TMAMedia`, URL — `/api/media/...`.
- Для импорта одного источника в LOCAL и Supabase запустите importer отдельно на каждом backend и повторите preview/apply. Квитанции, preview token, транзакция, ID карточек и авторство остаются в пределах выбранной БД. Между базами нет общей транзакции или автоматического переноса `card_id`; существующие ID источника должны быть валидны в целевой базе либо сопоставлены вручную через preview.
- Дедупликация охватывает этот импортёр и ранее зарегистрированные им ключи. Старые медиа с произвольными именами не сканируются и не скачиваются для вычисления хешей.
- Подготовленные файлы публикуются до транзакции карточек, с таймаутом и без автоматических повторов; существующие Storage-объекты не перезаписываются. Короткая запись каталога делает повтор после сбоя безопасным. Все карточки, ссылки и квитанции применяются одной транзакцией. При неуспехе привязки откатываются; уже загруженные файлы могут остаться непривязанными и переиспользуются при повторе. БД и Storage не образуют единой распределённой транзакции.
- Поиск существующих медиа читает только компактные поля каталога. Предпросмотр карточек не читает `image_data`, context, ответы или историю повторений.

## Модули и проверка

- `tools/admin/services/deck_import_sources.py`: прежние парсеры документов, версия манифеста и ссылки.
- `deck_import_media.py`: подготовка/хеширование/Storage и TMAMedia.
- `deck_import.py`: предпросмотр, permissions, квитанции и атомарное применение.
- `deck_import_limits.py`: ограничение тела запроса.
- `tools/admin/routers/deck_import.py`: два multipart-эндпоинта `/api/admin/author/folder-import/preview` и `/apply`.
- `tools/admin/static/js/folder_import.js`: отдельный интерфейс с сохранением прежних контролов выбора целевой папки.

Изолированные серверные проверки, без dotenv/сети/Production:

```powershell
python -c "from scripts.test_backend import isolated_suite; raise SystemExit(isolated_suite('scripts/tests/test_admin_folder_import.py'))"
```

Браузерный стенд создаёт одноразовую SQLite-БД, имитирует Storage и слушает только localhost:8059, отдельно от обычной консоли 8050:

```powershell
node node_modules/@playwright/test/cli.js test --config scripts/tests/browser/admin-folder-import.config.cjs
```

Настольные размеры: 1280, 1440, 1920 px. Скриншоты сохраняются в игнорируемом `test-results/`. По умолчанию используется настоящий Tailwind CDN админки; для автономного запуска его скрипт можно предварительно сохранить в игнорируемом `scratch/admin-import-assets/tailwind.js`.

Реальный Supabase Storage, LOCAL PostgreSQL и блокировки PostgreSQL этими тестами не проверяются. Миграций и деплоя нет.
