# Методический паспорт колоды

Паспорт импортируется в локальной админке «Автор» вместе с существующим текстовым
форматом карточек. Данные принадлежат колоде: `tma_deck.metadata.intro` и
`tma_deck.metadata.pedagogy`. Новых таблиц, миграции существующих данных и записей
в SRS/историю занятий нет.

## Аудит актуального локального кода

- Единое ядро — `api/services/author_service.py`; его используют локальная админка
  и `scripts/lerne_author_cli.py`. Заголовки `# Deck:` / `# Колода:` задают колоды;
  `---` и `<<<LERNE_CARD>>>` на отдельной строке разделяют карточки. Уровень и тема
  в CONTEXT принимают однострочный и многострочный вариант `::level` / `::topic`.
  Если значение отсутствует в карточке, оно наследуется из `intro.level` или
  `intro.topic` паспорта её колоды. Явные значения имеют приоритет независимо для
  каждого поля. При сохранении уровень попадает в CEFR metadata/tags карточки,
  тема — в её поле topics; CONTEXT остаётся пояснением.
- «Автор» уже принимает несколько файлов, добавляет имя файла как заголовок при
  отсутствии заголовка колоды и объединяет файлы. Этот механизм сохранён.
- Публикация ищет колоду по имени внутри выбранной папки. Каждый обычный повтор
  публикации добавляет новые карточки. Она не является дедупликацией/обновлением.
  Новый режим `passport_only` безопасно обновляет только существующие колоды.
- Bulk-save может вернуть частичные ошибки: «Автор» теперь отменяет всю транзакцию
  при таком ответе. Создание новой папки входит в ту же внешнюю транзакцию.
- Обновление карточек использует существующие preview-токены и receipts из
  `card_text_update.py`. Для документа с паспортами добавлен внешний токен и
  receipt: они связывают карточки, паспорт и исходные методические данные.
- `DeckIntroEditModal` обновляет intro через существующий metadata API/store;
  сохранение неизвестных полей intro (в том числе CEFR) и pedagogy проверено.
- `StudyView` передаёт `LessonCompletion` результаты из `sessionStats` через
  `calculateSessionStats`. Паспорт не участвует в расчёте точности/времени/ошибок.
- Обычный клиентский `batchCardParser.js` разбирает отдельные карточки. Импорт
  документов с паспортами выполняется в «Авторе», не в быстром импорте ученика.

Основные риски: повторная публикация карточек, потеря других ключей metadata,
неоднозначные имена колод, неполная запись при сбое и ложные выводы об освоении
при порядке SRS. Предусмотрены отдельное обновление паспорта, объединение полей,
блокировка конфликтов, транзакции и информационные подписи в интерфейсе.

## Формат версии 1

Маркеры паспорта занимают отдельные строки, расположены внутри своей колоды и
не совпадают с разделителями карточек. JSON извлекается **до** разбора карточек.

```text
# Deck: Самостоятельно построить мысль

<<<LERNE_PASSPORT>>>
{
  "schema_version": 1,
  "intro": {
    "title": "Самостоятельно построить мысль",
    "level": "B1",
    "topic": "Выражение противопоставления",
    "description": "Переход к самостоятельной речи",
    "goal": "Выражать собственные мысли без готового шаблона",
    "learning_outcomes": ["Выбирать конструкцию", "Строить предложения"],
    "estimated_time": "40–60 минут",
    "recommendations": "Предварительно пройти базовую практику"
  },
  "pedagogy": {
    "lesson_type": "practice",
    "stages": [
      {
        "id": "guided",
        "title": "С опорными словами",
        "goal": "Восстановить основные модели",
        "from_card": 1,
        "to_card": 2,
        "support": "high",
        "expected_skill": "Строить предложения с опорой"
      }
    ],
    "expected_result": "Ученик может выражать противопоставление в речи",
    "competencies": [{"id": "meaning", "title": "Смысловая связь"}],
    "assessment_criteria": [{"id": "word_order", "title": "Порядок слов"}],
    "review_recommendations": [
      {
        "id": "foundation_review",
        "title": "Базовая практика",
        "when": "Если трудно выбирать конструкцию",
        "reason": "Повторить основные модели",
        "competency_ids": ["meaning"]
      }
    ]
  }
}
<<<END_LERNE_PASSPORT>>>

<<<LERNE_CARD>>>

FRONT:
::exercise
Пример [[ответа]]
BACK:
ответа
CONTEXT:
::level B1

<<<LERNE_CARD>>>

FRONT:
Следующая карточка
BACK:
Ответ
CONTEXT:
```

В одном файле можно повторять `# Deck:` с разными паспортами и карточками.
Колоды без паспорта допускаются в том же документе.
Стандарт генерации и экспорта — `<<<LERNE_CARD>>>` перед каждой карточкой, в том
числе первой после паспорта. Импорт принимает прежний вариант без первого
разделителя, `---`, LF и CRLF. Колодный `::deck_id` до первого разделителя
применяется ко всем карточкам этой колоды; значения паспорта не переходят в
следующую колоду. Без паспорта или соответствующего поля intro наследования нет.

Интерактивные `@puzzle`, `@match`, `@wordbank`, `@free` распознаются только на
отдельной строке. Каждый начинает блок, включающий весь текст ниже (с пустыми
строками) до следующего структурного маркера или конца FRONT. `@options` остаётся
внутренним маркером банка слов. Наличие и положение `::exercise` не мешают
распознаванию этих блоков. После информационного блока отделите реальное
упражнение пустой строкой либо `::exercise`; внутри непрерывного `::task`,
`::source`, `::example` упоминания интерактивных маркеров остаются текстом.

Готовый небольшой файл для проверки формата: [deck_passport_example.txt](examples/deck_passport_example.txt).

### Обязательные поля и типы

| Поле | Контракт |
| --- | --- |
| `schema_version` | Обязательное целое число `1` на верхнем уровне |
| `intro` / `pedagogy` | Хотя бы один раздел-объект; разрешён частичный intro |
| Колода | Заголовок `# Deck:` либо явно заданный `default_deck_name` |
| `intro.level` | Если присутствует: `A1`, `A2`, `B1`, `B2`, `C1`, `C2` |
| `intro.learning_outcomes` | Массив строк; остальные основные поля intro — строки |
| `pedagogy.lesson_type` | Обязателен при передаче pedagogy: `theory`, `practice`, `review`, `assessment` |
| `stages[]` | Обязательные непустые `id`, `title`, `goal` и `support` |
| `support` | `high`, `medium`, `low`, `independent` |
| `from_card` / `to_card` | Оба целых, если указан диапазон; `1 ≤ from_card ≤ to_card` |
| `expected_skill` | Необязательная строка этапа |
| `competencies[]` / `assessment_criteria[]` | Объекты с непустыми `id` и `title`, необязательной строкой `description` |
| `review_recommendations[]` | Объекты с `id`, `title`; необязательные `when`, `reason`, `deck_id`, `competency_ids` |

ID используют латинские буквы, цифры, `_`, `-`, `.`, `:` и уникальны в своём
массиве. Глобального списка компетенций нет. Карточки автоматически к ним не
привязываются. `deck_id` рекомендации — информационная ссылка, не право записи
и не автоматически переносимый ID при публикации в другую папку.

JSON с дублирующимися ключами, NaN/Infinity, неверными типами или неизвестной
версией блокируется. Два паспорта одной колоды и конфликт deck_id блокируются.
Диапазон за пределами числа карточек файла даёт предупреждение: файл может быть
частичным. Пересекающиеся диапазоны допустимы. Отсутствие диапазона допустимо.

### Сохранение и совместимость

Обновляются только переданные поля разделов. Неуказанные поля сохраняются;
переданные массивы заменяются целиком. Для очистки используются `""` / `[]`.
`null` для основных полей не допускается. Другие ключи metadata, включая
`resources`, `is_learning` и расширения, сохраняются. В сохранённом pedagogy
автоматически появляется `schema_version: 1`; дополнительные JSON-поля остаются.

Экспорт включает только intro/pedagogy, не ресурсы и не пользовательские настройки.
При экспорте добавляется колодный `::deck_id`, поэтому паспорт колоды без карточек
тоже можно обновить. Карточки экспортируются в порядке `position`, затем `id`.
Имена и методические поля сохраняются при экспорте и повторном импорте.

## Использование в админке

1. Открыть «Автор» → «Публикация» и загрузить `.txt` / `.md` или несколько файлов.
2. Проверить количество карточек, паспорта, цели и этапы. Ошибки видны до записи.
3. Раскрыть «Просмотреть / редактировать паспорт». Основные поля и этапы
   редактируются отдельно; компетенции, критерии и рекомендации доступны в
   раскрываемом полном JSON. Изменения остаются черновиком.
4. Нажать «Проверить изменения» после правки. Не прошедший проверку черновик
   блокирует публикацию. Вновь выбранная папка сбрасывает прежний предпросмотр.
5. Выбрать папку → «Предпросмотр (Preview)»: сравнить поля «Было / Станет».
6. Нажать «Опубликовать в базу» для карточек и паспорта.

Для отдельного обновления: загрузить файл с паспортом (можно без карточек) либо
экспорт своей колоды, отредактировать паспорт и включить **«Обновить только
паспорта существующих колод»**. Выбрать существующую папку и проверить изменения.
Колода определяется по уникальному имени внутри папки; если в файле есть ID,
он должен совпасть. Новые колоды/карточки в этом режиме не создаются.

Существующая вкладка «Обновление» по-прежнему обновляет карточки с их ID. Если
файл содержит паспорта, они также сохраняются атомарно; изменённый или устаревший
паспорт не может примениться с прежним preview-токеном. Повтор с тем же request_id
возвращает подтверждённый результат. Для отдельного паспорта используйте режим
публикации `passport_only`, даже если в файле нет карточек.

CLI использует тот же сервис:

```powershell
python scripts/lerne_author_cli.py publish lesson.txt --folder-id 123 --user-id 42
python scripts/lerne_author_cli.py publish lesson.txt --folder-id 123 --user-id 42 --apply
python scripts/lerne_author_cli.py publish lesson.txt --folder-id 123 --user-id 42 --passport-only --apply
```

Это пример команд; без `--apply` работает существующий dry-run.

## Доступ и ограничения

Локальная админка сохраняет существующую модель доверенного локального оператора,
без добавления публичных пользовательских endpoints. Сервис проверяет owner/editor
папки и колод; явный user_id/настроенный AUTHOR_USER_ID/ADMIN_USER_ID имеет приоритет
над существующим определением владельца выбранного объекта. Passport-only нельзя
применить к произвольному deck_id вне выбранной папки. Клиентский metadata API
и offline-first сохранение вступления используют прежний механизм.

Маршрут — авторский план; диапазоны относятся к авторскому порядку, а не очереди
SRS. Итоговый экран сохраняет реальные метрики занятия и отдельно показывает
учебное описание/условные рекомендации автора. Оценок компетенций, подтверждения
завершённых этапов и автоматической диагностики здесь нет.

## Проверки

- `scripts/tests/test_deck_passport.py`: версии/типы, дубли, JSON, legacy, несколько
  файлов, структуры 09 (6 этапов), 12 (review), 13 (7 критериев), rollback, повторное
  применение, неизменность карточек/прогресса/истории, permissions, токены,
  пустой экспорт, полный roundtrip и порядок position/id.
- `app/src/utils/__tests__/deckPedagogy.test.js`: проекция и отсутствие ложной аналитики.
- `scripts/tests/browser/deck-passport.spec.cjs`: настоящие React-компоненты, сохранение
  intro, Classic/mobile 320/375/430/768/1080, RU/EN, безопасное отображение HTML,
  локальный HTML/JS админки с подменённым API и режим passport-only.
- Все записи backend-тестов идут в одноразовую SQLite. В браузере API подменены.
  PostgreSQL-конкуренция, реальная авторизация окружения и полный пользовательский
  цикл с рабочей БД автоматически не проверялись.

Ручная проверка перед использованием: реальный файл Antigravity → «Автор» →
предпросмотр/редактирование → публикация в тестовую колоду → вступление → занятие
→ реальные итоги → экспорт → режим «Только паспорт». Проверить выбор нужной папки,
CEFR, число этапов, условные рекомендации и отсутствие новых карточек при повторе.

Смежные проверки текущего локального дерева: три прежних падения в
`exerciseParsers.test.js` (уровень массового импорта, сохранение ручного перевода,
синонимы), а два Python-теста старого клиентского roundtrip ссылаются на отсутствующие
`cardTextSerializer.js` / `cardTextUpdateParser.js`. Эти модули не изменялись в задаче.

Расширенная проверка существующих browser-сценариев дала 18 PASS / 14 FAIL:
13 ожиданий старого `StudyFinished` при включённом по умолчанию `LessonCompletion`,
одно ожидание высоты кнопки 64 px при текущем CSS 48 px. Настройка показа completion,
выбор экранов в StudyView и существующая высота кнопки в этой задаче не изменялись.
Отдельные новые тесты паспорта явно задают нужные настройки и проверяют оба варианта.
