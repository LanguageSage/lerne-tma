## Алгоритм и duplicate words

Token ID — исходный индекс authored слова. Evaluator получает только массивы IDs, строит Map направленных соседств target order и проверяет каждую фактическую пару пользователя. Для target `[0,1,2,3,4]` и ответа `[0,2,1,3,4]` неправильны `0→2`, `2→1`, `1→3`; `3→4` правильна. ID part: `puzzle:boundary:0-2` и аналогичные.

Bad part содержит только `id/status/errorType/errorCode/hint`: `word_order`, `exercise.word_order`, «Проверь порядок рядом с этим местом.». Correct part содержит только `id/status`. Public result не содержит target order, expected sentence, правильного следующего слова, правильной позиции или значений ответов.

Completion требует полного точного совпадения порядка IDs, включая длину. Это дополнительно исключает неполные/повторные/чужие tokens и обрабатывает одно слово без boundary. Пустой target не принимается. Два слова дают одну boundary. Поддерживается ровно один authored порядок, синтаксис не менялся; stateless adapter отделён от UI и session, что позволяет позже расширить правила accepted orders без нового pipeline.

В `Ich sehe den Mann und den Hund.` два `den` имеют IDs 2 и 5. Их обмен сохраняет текст предложения, но нарушает четыре directed boundaries и не принимается. Текст не служит идентификатором part.

## UX и очистка stale feedback

Bad boundaries обозначены маленьким красным X, correct — мягкой зелёной галочкой. После ошибки target остаётся нейтральным; одна строка «Проверь порядок возле отмеченных мест.» не дублируется у каждого маркера. Маркер прикреплён к следующему chip и переносится вместе с ним. Его место зарезервировано и до Check, поэтому очистка feedback не сдвигает геометрию drag. Chips сохраняют пользовательские font/color/size, длинные слова переносятся; touch targets минимум 44 px. Собранные chips стали настоящими кнопками с keyboard focus. Boundary labels и hint локализованы через существующий `tr`.

Correct boundary — только визуальная информация: Puzzle не использует generic `isLocked(partId)` для отдельных tokens. До полного completion все собранные слова можно двигать/удалять. После success они блокируются целиком.

Add, remove, drag start/reorder и Reset вызывают generic `clearCurrentFeedback()`. До completion он очищает только result, сохраняя counters, incorrectParts и error history. Для completed session очистка — no-op: сохраняется финальный verdict для evidence. Reset очищает сборку, но не учебную историю. Transient drag state не сохраняется.

## Attempts и cumulative evidence

Один явный Check = одна attempt. Каждый неправильный Check добавляет одну mistake независимо от количества bad boundaries; повторный Check того же неправильного порядка тоже считается. Click/add/remove/drag/Reset/flip/remount не считаются.

| Сценарий | attempts | mistakes | isFirstTry | completed |
| --- | ---: | ---: | --- | --- |
| Сразу правильно | 1 | 0 | true | true |
| Неверный Check, затем edit | 1 | 1 | — | false |
| Затем правильный Check | 2 | 1 | false | true |
| Два одинаковых неверных Check | 2 | 2 | — | false |
| Ошибка, Reset, правильная сборка и Check | 2 | 1 | false | true |

До success evidence отсутствует и `onTrainerAnswer` не вызывается. Поэтому GradeButtons не появляются после ошибки. Только completion вызывает `onTrainerAnswer(card.id, evidence)`, ровно один раз. Например, ошибка для `[0,2,1,3,4]`, затем правильный Check:

```json
{
  "isCorrect": true,
  "completed": true,
  "isFirstTry": false,
  "attemptCount": 2,
  "mistakeCount": 1,
  "gradingSummary": {
    "final_verdict": "correct",
    "error_types_seen": ["word_order"],
    "error_codes_seen": ["exercise.word_order"],
    "incorrect_parts": ["puzzle:boundary:0-2", "puzzle:boundary:2-1", "puzzle:boundary:1-3"],
    "final_evaluator": "rules"
  }
}
```

Core объединяет исторические part IDs и error codes/types без дублей. Успех заменяет текущий result, сохраняя cumulative историю прежних ошибок.

## Lifecycle и Knowledge

Владелец состояния прежний: `StudyCard.exerciseStates[card.id:historyIndex]`. `ExerciseRenderer` задаёт Puzzle `key={reviewKey || exerciseCard.id}`. Unconditional mount/card-ID reset удалён. `onSaveState` хранит selectedPuzzles, showTranslation и evaluationState, включая completed. Flip/remount той же review восстанавливает порядок, перевод, result и counters. Новый historyIndex и другая card получают чистую session. Completed remount не повторяет callback; следующие Checks отклоняются core.

Поток: `puzzleEvaluation → exerciseEvaluation/useExerciseEvaluation → onTrainerAnswer → StudyView → grade → knowledgeCaptureService → Dexie outbox → Knowledge sync`. Новый store/session/evidence schema/API/table/migration не добавлены. `grading_summary` остаётся additive в существующем schema_version=2 hybrid evidence. Capture-тесты используют настоящую session и fake IndexedDB. Python regression сравнивает Mastery score/weight с summary и без него для одинаковых attempt_count 1/2/3/5. Mastery formula и StudyView/capture runtime не менялись.

## Ограничения и следующий шаг

Live backend/production deployment и реальные мобильные устройства не проверялись: browser API/WebSocket изолированы моками, Knowledge использует IndexedDB/SQLite fixtures. UI скрывает решение в feedback; authored предложение и ID индексы остаются в исходных локальных данных карточки, как прежде. Грамматический inference, AI и альтернативные authored orders не добавлены. Изменение содержимого card внутри активной review и перенос in-memory state между версиями не входят в текущий lifecycle contract.

После KI-08.3 рекомендуется устранить три baseline parser defects отдельной задачей и закрепить общий KI-08 lifecycle/feedback regression suite в CI. Следующее развитие core — использование накопленной error history в существующей Knowledge diagnostics; расширение accepted Puzzle orders стоит делать только вместе с явно определённым authored синтаксисом и отдельными педагогическими требованиями.
