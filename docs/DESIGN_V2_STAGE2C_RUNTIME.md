# Design V2: этап 2C — речь, фоны и текстовые эффекты

Дата: 2026-10-29. Продолжение [этапа 2B](DESIGN_V2_STAGE2B_PUZZLE_TRAINER.md)
в рамках [перехода только на V2](../.agents/AGENTS.md#design-v2-архитектурное-решение).
Этап завершает этот участок runtime-переноса; полное удаление Legacy и миграция
личных настроек остаются следующими этапами.

## Единые источники оформления

| Элемент | Источник и применение |
| --- | --- |
| Речевой target и распознанная фраза | `front.mainText` через существующий `getDesignStylesFromV2` |
| Речевой success/wrong | Существующие семантические токены choice, без отдельной речевой палитры |
| Фон физических FRONT/BACK | `front.card.background` / `back.card.background` через общий `CardBackground` |
| Answer/context в CardForm | Те же роли V2, что в StudyCard; изменение шрифта пересчитывает высоту поля |
| Типографика списка и образцов настроек | Общий `getDesignTextStyle`, включая lineHeight и shadow |
| `back.context.color: auto` | Существующий `getHarmonizedContextColor` от `back.answerText.color` |
| Свечение интерактивного текста | `currentColor`, чтобы выбранный/correct/wrong цвет определял и свечение |

`StudyCardSpeech` принимает явный `designConfig` для scoped preview. Без prop
используется прежний effective config: активный локальный draft или опубликованный
дизайн; явный null сохраняет прежнюю fallback-границу. Смена дизайна не сбрасывает
распознавание, ввод и текущий review. Reset успешного ответа при новом review
выполняется при смене ключа, без дополнительного setState из effect.
Политика распознавания, проверки речи, переходов, оценки и SRS сохранена.

Тени none/shadow/glow/neon/outline/glass теперь применяются общим text helper
в runtime и настройках. Glow поддерживает также HSL/RGBA/currentColor через
`color-mix`, сохраняя прежний результат для шестизначного HEX. CSS-токены теней
и auto context вычисляются из того же helper, без второй реализации.

## Фоны и безопасное дополнение старого V2

`CardBackground` переиспользуется в StudyCard, отдельном TrainerView, CardForm,
образцах FRONT/BACK и настоящих упражнениях в настройках. Три копии resolver
автоматической темы удалены; используется существующий `getResolvedStyle`.
Режим reverse не меняет принадлежность фона физической стороне карточки.

Поддерживаются прежние имена тем, auto, сохранённый `custom_<filename>`, HEX,
RGB/HSL, transparent/currentColor и линейный/радиальный градиент с RGB/HSL stops.
Нормализатор отклоняет URL-фоны, в том числе добавленные после градиента,
и пути custom с разделителями/`..`. Видео и custom media рисует прежняя ветка
CardBackground; нового механизма загрузки или хранилища нет.

Новое поле имеет default `''`: старый V2 без заданного фона продолжает показывать
прежний личный `cardBgFront`/`cardBgBack`. Это временная граница существующей
совместимости до переноса данных. Подстановка standard вместо пустого значения
сейчас потеряла бы видимое личное оформление. При явно выбранном V2 фоне
он используется напрямую, независимо от старого значения.

Ручной импорт Legacy и конвертация пресетов теперь записывают фон в настоящие
V2-поля: прежние `_legacyBg*` отбрасывались нормализатором. Ненужные боковые
`legacyBgFront/Back` удалены. Это исправление ручного converter, а не доказательство
полноты автоматической миграции всех V1-настроек; её аудит и backup ещё нужны.

В контролах поверхности добавлен выбор темы или своего цвета/градиента. Свой
текст применяется на blur, чтобы неполный ввод не сбрасывался нормализатором
на каждой клавише. Прежние permissions, draft/publication и local preview
остаются владельцами применения дизайна. Speech preview использует настоящий
компонент в disabled fieldset и не запускает микрофон.

## Удалённые дубли и неработающие настройки

Удалены неиспользуемые `TypographyPreview.jsx` и `CardListPreview.jsx`;
образцы настроек используют общие text/background helpers. Удалён переключатель
auto palette, который не управлял цветами вариантов. Явные цвета состояний
остаются единственным источником, baseColor сохраняет реальное назначение
гармонии Quiz-иконок. `exercises.paletteMode` и `exercises.bodyText` пока
сохраняются как deprecated поля, чтобы не уничтожать сохранённые данные до
миграции. Renderers не получают из них конкурирующее оформление.

| Адресные runtime/token unit-тесты после финальной валидации | 13/13 PASS, входят в suite приложения |
| ESLint 18 изменённых JS/JSX-файлов | PASS |
| `node --check` нового browser suite | PASS |

| Регрессии дизайна 1/2A/2B и речи | 82/82 PASS |
| Новый `design-runtime-v2.spec.cjs`, финальный полный повтор | 13/13 PASS |
| Дополнительный scoped gradient preview после финальной валидации | 1/1 PASS |

Общий запуск 95 сценариев дал 94 PASS и одну ошибку тестовой установки reduced
motion после монтирования. Текущий Framer hook фиксирует предпочтение при mount;
тест перенесён на установку media preference до загрузки приложения, assertions
об отсутствии transform сохранены. Затем все 13 новых сценариев прошли повторно.
Поддержка смены системного reduced motion без remount этим этапом не менялась.
Статический liquid теперь сохраняет выбранную палитру темы без движения.

Проверены 320/375/430/768/1280 CSS px, речь и transcript, новый review, речевой
follow-up после Puzzle, сохранение микрофона/ввода при смене дизайна, все девять
типов карточек и reverse, сохранение старых личных фонов, CardForm/source,
semantic glow, scoped previews без публикации и reduced motion при загрузке.
Визуально просмотрены совпадающие V1 речевые снимки до/после на 375px, V2 speech
success на mobile/desktop, мобильный редактор и scoped speech в настройках.

Данные синтетические, API подменены, внешняя сеть заблокирована; сервер запущен
без `.env` с isolated proxy. Реальные БД, микрофон/ASR, внешние шрифты/видео,
физические устройства и миграция online/offline не проверялись. Артефакты
находятся только в ignored `local/test-data/design-v2-stage2c-*`.

## Следующий этап

До удаления Legacy нужны аудит и безопасная версия миграции личных настроек
и пресетов: backup, определённый приоритет личного и опубликованного оформления,
повторный запуск без потери данных, online/offline, смена аккаунта и восстановление.
После успешной миграции и проверок удаляются fallback, adapter и старые поля/
хранилища оформления. Legacy-формат учебного контента к этой задаче не относится.
Backend, stores, пользовательские данные и сохранённые пресеты этапом 2C
не мигрировались и не удалялись. Commit/push/deploy этапа 2C не выполнялись.
