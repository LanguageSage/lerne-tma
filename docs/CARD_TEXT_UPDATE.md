# Обновление существующей колоды из текстового файла

Меню колоды → **«Обновить из файла»** → UTF-8 `.txt`/`.md` → предпросмотр →
**«Применить изменения»**. Обычный быстрый импорт продолжает создавать карточки,
включая старые файлы без ID; режимы не смешиваются.

## Идентификация и парсер

Экспорт использует сохранённые числовые `TMA_Card.id` и `TMA_Deck.id`. Миграция
и UUID не нужны. Перед **каждой** секцией FRONT находятся две служебные строки:

```text
::deck_id 10
::card_id 101
FRONT:
der [[bequeme]] Schuh
BACK:
удобная обувь
CONTEXT:
::level B1

<<<LERNE_CARD>>>

::deck_id 10
::card_id 102
FRONT:
Haus
BACK:
дом
CONTEXT:
```

`cardTextMetadata.js` извлекает только маркеры **до FRONT**. Литералы этих строк
внутри учебного содержимого сохраняются. `cardTextUpdateParser.js` использует
существующие разделитель, секционный/batch parser, определение типа и парсеры
упражнений; второй независимый язык карточек не вводится. Для обслуживания
проверки строже: обязательны непустой FRONT и единственные FRONT/BACK/CONTEXT
в каноническом порядке, валидные идентификаторы и распознаваемые упражнения.
Все ошибки всех блоков собираются сразу и блокируют применение всего файла.
Явно пустой BACK и пустые строки CONTEXT сохраняются при обновлении.

Числовой ID сопоставляется с текущей БД выбранной колоды. Без ID карточка
показывается как новая; флажок добавления новых по умолчанию выключен. Неизвестные
или удалённые ID предупреждают и блокируют применение. Для намеренного создания
новой карточки нужно удалить её `card_id` и отдельно разрешить добавление.
Служебные ID никогда не записываются в front/back/context. Заголовки экспортов
папок игнорируются; файл с ID нескольких колод нельзя применить к одной колоде.

## Предпросмотр и защита

POST `/decks/{id}/text-update/preview` получает только контент и идентификаторы.
Сервер проверяет существование колоды, owner/editor через существующий механизм
collaborative permissions, принадлежность каждой карточки, заявленный deck_id,
дубли ID и структуру контента. Гости, viewer и чужая приватная колода запрещены.
Чужие карточки не раскрывают содержимое в ответе.

Возвращаются количество обновлений, unchanged, новых, missing и ошибок, а также
список изменённых полей с «было/стало». Сравниваются front/back/context, эффективный
CEFR и topics после нормализации CRLF и внешних пробелов. Timestamps, позиция,
аудио, SRS и статистика не участвуют в сравнении. Удаление маркера уровня у
существующей карточки сохраняет её уровень; указанный новый CEFR меняет уровень.

Fingerprint связывает предпросмотр с присланным контентом и текущим учебным
содержимым всей колоды. Если другой редактор изменит контент или состав колоды,
apply вернёт 409 и предложит обновить предпросмотр. Изменение прогресса обучения
не делает предпросмотр устаревшим.

## Применение и сохранность

POST `/decks/{id}/text-update/apply` повторно проверяет permissions и контент.
Сервер выполняет квитанцию запроса, все UPDATE/CREATE и отметку изменений колоды
одной транзакцией. На PostgreSQL существующие строки блокируются FOR UPDATE.
Ошибка любой карточки или записи откатывает всю операцию.

UPDATE ограничен принадлежностью выбранной колоде и перечислением полей контента.
`save_card` намеренно не вызывается: его побочные эффекты обычного редактора здесь
не нужны. Тип меняется только вместе с front, а технический updated_at — только
при реальном изменении. Правка CEFR сохраняет остальные metadata и произвольные
теги, в том числе их JSON-представление. Карточки, пропущенные в файле, не меняются.
Новые добавляются в конец только по явному подтверждению.

**SRS, интервалы, статистика, история обучения/редактирования, прогресс всех
пользователей, флаги, медиа, авторство и остальные поля сохраняются.** Наборы
`TMAProgress` / `TMAReviewHistory` вообще не записываются этим сервисом.

Перед HTTP apply клиент сохраняет точный payload и request_id в Dexie syncState
`text-update:{deckId}`, отдельно для каждого аккаунта. Это не учебная карточка
и не review-событие; syncService не отправляет его как обычную синхронизацию.
Если ответ потерян или страница перезагружена, пользователь повторяет тот же
запрос. Квитанция `TMAOfflineBatch` возвращает прежний результат и не создаёт
повторных новых карточек. Изменение payload с прежним request_id запрещено.
Успешный ответ очищает попытку и обновляет списки; сбой чтения списка после commit
не запускает повторное применение. Подтверждённые 403/404/409/422 очищают попытку.

## Файлы реализации

- `app/src/utils/cardTextSerializer.js`, `cardTextMetadata.js`, `cardTextUpdateParser.js`:
  экспорт ID, извлечение metadata, существующий parser/import pipeline.
- `app/src/utils/batchCardParser.js`: необязательное сохранение форматирования
  CONTEXT, default обычного импорта не изменён.
- `app/src/services/cardTextUpdate.js`: online preview/apply, проверка dirty данных,
  сохранение попытки; используется авторизованный networkApi без offline fallback.
- `app/src/components/modals/DeckTextUpdateModal.jsx` / `.css`: выбор файла,
  сводка, ошибки, список изменений, явное добавление новых, подтверждение и результат.
- `DeckCardItem.jsx`, `App.jsx`, `components/modals/index.js`, `useUiStore.js`,
  `utils/navigation.js`: пункт меню и жизненный цикл диалога.
- `app/src/i18n/messages/en.json`, `uk.json`: переводы интерфейса; русский — source keys.
- `api/routers/decks.py`: строгие Pydantic-модели и два синхронных endpoint.
- `api/services/card_text_update.py`: authoritative compare, permissions,
  транзакция content UPDATE и идемпотентная квитанция.

  изолированными mock API: весь UI-цикл, новое явное добавление, потерянный ответ
  и перезагрузка, все ошибки, stale/retry, readonly, offline/dirty, пустой/большой

  серверных. Python compilation, полный frontend lint и production build.

SQLite тесты проверяют атомарность и сохранность; реальная конкуренция PostgreSQL

три сбоя фикстур (guest restore и отсутствующий `_learning_key` в stub) также
воспроизводятся на исходном тесте Git HEAD; файлы этого пути не менялись.

## Ограничения первой версии

- Только одна колода, online в веб-версии. Native/offline режим не поддерживает
  обновление из файла; для него используйте веб-версию. Локальные dirty изменения
  колоды сначала синхронизировать. Экспорт offline работает.
- Файл до 5 МБ, до 5000 карточек, серверные ограничения длины полей.
- Нет удаления, массового обновления папки, merge, версий, backup или rollback UI.
- Зарезервированные границы формата не экранируются. Неоднозначные строки
  уровня/темы в CONTEXT продолжают интерпретироваться существующим parser;
  предпросмотр показывает полученный контент перед подтверждением.
- Медиа и произвольные теги не редактируются этим файлом, но существующие сохраняются.
- Сравнение по полям; посимвольного diff нет. Снимок всего контента колоды означает,
  что изменение другой карточки требует повторного предпросмотра.
