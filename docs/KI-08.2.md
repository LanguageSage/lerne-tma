## 4. Match и common contract

Существующий парсер сохраняет ID исходных строк: `match:left-1`, `match:left-2` и т. д. Adapter сравнивает нормализованные правые значения, создаёт parts через `createExerciseEvaluation` и передаёт результат в единственный `useExerciseEvaluation`. `requiredPartIds` не позволяет завершить упражнение после одной правильной пары. Непройденные пары не маркируются искусственными ошибками.

Правильная пара фиксируется в существующем userMatches, получает success-рамку и одинаковую метку на обоих элементах, блокируется. Неправильная не фиксируется: оба элемента доступны, выбранная левая часть получает `other / exercise.wrong_match` и короткую подсказку. Полный список соответствий удалён из feedback UI. Публичный contract содержит только id/status/error metadata/hint. Тексты решений и введённые значения в него не входят.

Повторяющиеся правые значения взаимозаменяемы после прежней whitespace-нормализации; один физический элемент используется один раз. Проверка работает при выборе слева направо и справа налево.

## 5. Семантика попыток Match

Использовано разрешённое заданием исключение из предпочтительной модели. `attemptCount` сохраняет прежний смысл учебной попытки решения: **количество неправильных сопоставлений + итоговый успех**. `mistakeCount` — число неправильных сопоставлений. Все завершённые pair interactions считаются отдельно в `gradingSummary.interaction_count`. Выбор первого элемента, отмена, повторный клик по заблокированной паре, flip/remount не считаются.

Причина: Mastery v1 проверяет `first_try_correct === (attempt_count === 1)` и снижает score с ростом attempt_count. Чистое решение из трёх пар с preferred attemptCount=3 и firstTry=true стало бы невалидным evidence; firstTry=false штрафовал бы безошибочное решение. Формула и валидатор Mastery не менялись. Новый descriptive счётчик не влияет на score.

| Сценарий: три пары | attemptCount | mistakeCount | isFirstTry | interaction_count |
| --- | ---: | ---: | --- | ---: |
| Все три сразу правильно | 1 | 0 | true | 3 |
| Правильно → ошибка → исправление → последняя пара | 2 | 1 | false | 4 |
| Две ошибки и три правильных пары | 3 | 2 | false | 5 |

До completion attemptCount содержит число ошибок; финальный успех добавляет единицу. Только completion создаёт evidence и вызывает onTrainerAnswer.

## 6. Quiz retry

Сохранён существующий UX выбора варианта и отдельной кнопки «Проверить». Изменение выбранного варианта до Check не увеличивает counters. После неправильной проверки только выбранный option получает `word_choice / exercise.wrong_choice`, красную рамку и «Попробуй другой вариант.». Он отключается, текущий выбор очищается; остальные доступны. Правильный вариант не подсвечивается и не раскрывается. Следующая правильная проверка завершает упражнение и передаёт cumulative evidence. История прежних ошибок сохраняется, даже когда текущий result уже correct.

## 7. Специальные Quiz policies

В стандартном Quiz возможны несколько starred вариантов. Это существующие альтернативные правильные ответы для single-choice: любой starred option принимается, выбирать все не требуется. Adapter использует option.isCorrect, а не только первый correctAnswerId. Проверено unit и реальным renderer.

Отдельные LiD exam/practice работают через `LidQuestionCard`, `LidExamView`, `useLidStore`, вне ExerciseRenderer. Exam сохраняет выбранный ответ без раскрытия правильности. Practice сразу показывает выбранную ошибку и правильный вариант по существующей policy, позволяет менять выбор. Оба режима проверены в браузере и не изменялись. Отдельной one-shot policy/флага у StudyCardQuiz и его callers не обнаружено; добавлять новый speculative flag не требовалось.

## 9. Lifecycle

Владелец lifecycle прежний: `StudyCard.exerciseStates[card.id:historyIndex]`. Сохранены UI selection, confirmed Match mapping/порядок правых элементов, Quiz optionOrder и snapshot общей session. Flip того же review восстанавливает progress, ошибки и counters. Новый historyIndex той же карточки и другая карточка получают свежую keyed session. Completed session не выполняет повторный check; восстановление не вызывает callback. Browser harness проверяет ровно один итоговый onTrainerAnswer для каждого review.

## 10. Knowledge Layer

## 12. Browser и визуальная проверка

Match: wrong pair → local feedback, оба элемента доступны → correct pair locked → flip сохраняет пару → оставшиеся пары → grade buttons. Quiz: wrong Check → local hint, правильный option нейтрален → flip сохраняет порядок/ошибку → другой вариант → success → grade buttons. Тесты запускаются с моками API/WebSocket и запретом внешних запросов.

Для retry и success сделаны screenshots и проверки отсутствия горизонтального overflow на 320/375/430/768/1280 px. Выполнен визуальный просмотр mobile/desktop screenshots: локальная подсказка, рамки, spacing, доступность вариантов и footer читаются; сохранены существующие настройки Georgia и цвет карточки. Русский и английский feedback проверены в браузере, украинский перевод добавлен. Локальные QA-изображения находятся в ignored `test-results/match-quiz-feedback-*`, не включены в commit.
