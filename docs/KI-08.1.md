# KI-08.1 — Unified Exercise Feedback Core + Word Bank + Trainer

Branch: `feature/ki-08-unified-exercise-feedback`.
Base: freshly fetched `origin/main`, `e2b13a7`.

## Implementation

`app/src/utils/exerciseEvaluation.js` owns the public v1 part contract and a small
deterministic evaluation session. The public feedback contains only part IDs,
correct/incorrect status, safe error metadata and hints. It excludes expected and
submitted answers. IDs are normalized to strings; Trainer uses its existing
zero-based gap IDs, Word Bank preserves authored gap IDs.

The shared session tracks the latest part feedback, completion, educational
attempt/mistake counters and unique accumulated incorrect parts/error types/codes.
`app/src/hooks/useExerciseEvaluation.js` connects that session to React state.
It does not introduce storage or another review lifecycle mechanism.

### Word Bank

`checkWordBankAssignments()` keeps its existing `results` and `allCorrect` fields
and adds `evaluation`. Confirmed gaps are disabled, stay assigned, and keep their
options consumed. Wrong gaps remain removable/replaceable. Check activates the
first incorrect gap. Editing clears only that gap's stale feedback. Its local hint
is “Проверь этот пропуск и выбери другой вариант.” The Check action remains
available until all gaps are correct; the option bank has space above the existing
pinned action button.

### Trainer

`app/src/utils/trainerEvaluation.js` compares each gap using the existing
`normalizeAnswer` and pipe-separated accepted variants. Input and choice controls
are locked individually when correct. Wrong controls stay editable with their
submitted values, and Check focuses the first incorrect control. Typed/choice
correction badges and automatic expected-answer reveal are removed. The former
reset-all action is replaced by repeated checks and a disabled completed action.

Safe metadata:

| Gap | Type | Code | Hint |
| --- | --- | --- | --- |
| Word Bank / ordinary choice | `word_choice` | `exercise.wrong_choice` | Word Bank hint / “Проверь этот вариант.” |
| Input | `other` | `exercise.input_mismatch` | “Проверь введённую форму в этом месте.” |
| Explicit `isAffix` (input or choice) | `other` | `exercise.affix_mismatch` | “Проверь окончание.” |

Hints use the existing `tr` interface locale system with Russian source strings
and English/Ukrainian translations. Font/color customization is inherited.
Affix controls stay attached to their word; their hint appears below the word.
`aria-invalid`, `aria-describedby` and local status messages expose feedback to
assistive technology.

### Attempts and Knowledge evidence

Each enabled explicit Check/Enter increments `attemptCount` once. Each failed
check increments `mistakeCount` once, regardless of the number of wrong gaps.
Editing and incomplete submits do not increment either counter. Completed
sessions ignore later checks and cannot report success again.

Intermediate failures have no `onTrainerAnswer` callback. The StudyView grading
controls therefore stay closed on the front after a failed check. On final
success the existing callback receives, for example:

```js
{
  isCorrect: true,
  completed: true,
  isFirstTry: false,
  attemptCount: 2,
  mistakeCount: 1,
  gradingSummary: {
    final_verdict: 'correct',
    error_types_seen: ['word_choice'],
    error_codes_seen: ['exercise.wrong_choice'],
    incorrect_parts: ['gap-2'],
    final_evaluator: 'rules'
  }
}
```

StudyView retains this evidence until grading, then the unchanged
`knowledgeCaptureService` writes it into the existing hybrid schema v2
`exercise_evidence.grading_summary` and Dexie outbox. No endpoints, tables,
migrations, scoring changes, AI calls or extra pipeline were added. A regression
asserts that adding these descriptive fields leaves Mastery v1 scoring identical.

### Lifecycle

StudyCard remains the owner of `exerciseStates[card.id:historyIndex]`.
Saved state includes selected values, active Word Bank gap, Trainer translation
toggle, part feedback, counters, accumulated errors and completion. ExerciseRenderer
keys only Word Bank/Trainer by the existing reviewKey so a new card/review starts
cleanly while remounting the front during a flip restores the same review's state.
Quiz/Puzzle/Match components and the KI-07 free-text evaluator are unchanged.

## Limits and KI-08.2

State is scoped to the existing in-memory review, including exercise remounts;
page reload persistence is outside this change. Evaluation uses the existing
parser and normalization semantics. Hints intentionally do not infer grammatical
causes. Quiz/Puzzle/Match/free-text adoption of the part contract is deferred.
Browser checks use local API fixtures rather than a live backend.

For KI-08.2, select the next deterministic exercise type (Quiz or Match), map its
parts into the same contract, and reuse these retry/history/evidence invariants.
Any richer grammar feedback should rely on explicit exercise metadata and get
separate regression coverage. Resolve the existing parser failures independently.
