# Общий формат Lerne

## Карточки и вывод

При генерации выдавай только текст импорта: без вступления, комментариев, нумерации карточек и внешних Markdown code fences. JSON карточек и `card_data` не используются; исключение для паспорта указано ниже.

Перед каждой карточкой, включая первую после паспорта, ставь `<<<LERNE_CARD>>>` отдельной строкой. После последней карточки разделитель не нужен. При генерации всегда выводи секции `FRONT:`, `BACK:`, `CONTEXT:` в этом порядке, с содержимым на следующих строках. FRONT непустой; допустимость пустого BACK/CONTEXT определяется типом.

- FRONT — задание, учебный материал или вопрос.
- BACK — перевод всей обрабатываемой фразы на язык пользователя либо ответ/объяснение по назначению карточки. Особые требования Free Text и Word Bank — в их файлах типов.
- CONTEXT — содержательное пояснение ответа или правила без повторов; сохраняй необходимые нюансы и различия вариантов. Тема и уровень — отдельные метаданные, а не замена пояснению.

```text
<<<LERNE_CARD>>>
FRONT:
::task
Ergänzen Sie die Form.
::exercise
Er [[war]] nach Hause [[gegangen]].
BACK:
Он ушёл домой.
CONTEXT:
Plusquamperfekt: war/hatte + Partizip II.
::level
B1
::topic
Plusquamperfekt
```

## Структура FRONT

Маркеры занимают отдельные строки:

| Маркер | Содержимое |
| --- | --- |
| `::task` | Инструкция |
| `::options` | Исходные варианты или словарь |
| `::source` | Текст для чтения, цитата, перевод или контекстная подсказка |
| `::example` | Пример выполнения; блок можно повторять |
| `::exercise` | Тело упражнения |

Информационные блоки размещай перед упражнением. Подсказки и переводы выноси в `::source`, а не в скобки внутри тела упражнения; не раскрывай там проверяемый ответ.

После информационных блоков отделяй обычное тело упражнения явным `::exercise`. Для отдельных строк `@puzzle`, `@match`, `@wordbank`, `@free` он необязателен: они начинают блок до следующего структурного маркера или конца FRONT; пустые строки внутри сохраняются. От предыдущего информационного блока директиву отделяй пустой строкой либо `::exercise`, иначе она останется буквальным текстом. `@options` — часть Word Bank, не `::options`. Правила `@theory` — в [types/theory.md](types/theory.md).

Одна карточка содержит одну механику упражнения; ввод и inline-выбор совместимы в Trainer. Разные упражнения разделяй на карточки: несколько интерактивных директив в одном FRONT не создают последовательность заданий.

Не используй псевдомаркеры `@free_text`, `@word_bank`, `::answer` или `::hint`. Изображения можно прикрепить в интерфейсе; текстовый контракт не требует картинок и не задаёт их синтаксис.

## Метаданные и паспорт

В CONTEXT указывай известные `::level` (A1–C2) и `::topic`, каждый маркер и значение — отдельными строками.

Для документа «Автора» сохраняй заголовки колод `# Deck: ...` / `# Колода: ...` и существующий паспорт: JSON между отдельными строками `<<<LERNE_PASSPORT>>>` и `<<<END_LERNE_PASSPORT>>>` перед карточками своей колоды. Формат паспорта — [DECK_PASSPORT.md](../docs/DECK_PASSPORT.md). Он импортируется «Автором», а не быстрым импортом карточек.

Отсутствующие уровень и тема наследуются независимо из `intro.level` и `intro.topic` паспорта своей колоды; явные значения карточки важнее. Без паспорта указывай известные метаданные явно. При обработке экспорта сохраняй служебные ID перед FRONT. Старые разделители `---` и отсутствие разделителя перед первой карточкой принимаются «Автором»; для нового вывода используй формат выше.
