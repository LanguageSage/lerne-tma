# Lerne TMA: общие правила работы

## Подход к изменениям

- Перед изменением проверь рабочее дерево, затрагиваемый код и его потребителей. Сохраняй чужие незавершённые изменения.
- Определи ожидаемое поведение и критерий завершения. Для ошибки сначала воспроизведи её или собери доступные доказательства; отделяй гипотезу от установленной причины.
- Выбирай минимальное законченное решение без несвязанных рефакторингов, зависимостей и абстракций.
- Самостоятельно выполняй разрешённые локальные изменения и проверки. Уточняй существенные неизвестные требования; не запрашивай повторное разрешение на согласованную работу.
- Сохраняй совместимость API, настроек и данных. Проверяй Telegram, standalone и офлайн-поведение, когда изменение их затрагивает.
- Проверяй права на объекты на сервере: ограничения интерфейса не заменяют авторизацию.
- Не раскрывай секреты и персональные данные в логах. Локальная задача не разрешает операции с рабочими данными пользователей или публикацию.

## Архитектурная карта и топология

- Сквозная матрица фич и карта диагностики: `.agents/ARCHITECTURE.md`. Сверяйся с ней в первую очередь для мгновенного определения затронутых файлов (UI $\to$ State $\to$ API $\to$ DB).

## Скиллы проекта

Подключай подходящие к задаче инструкции:

- `.agents/skills/lean-code/SKILL.md`: переиспользование и структура кода.
- `.agents/skills/tma-ui/SKILL.md`: интерфейс, доступность и Telegram.
- `.agents/skills/fastapi-backend/SKILL.md`: API и серверная логика.
- `.agents/skills/db-mgmt/SKILL.md`: миграции, транзакции и синхронизация.
- `.agents/skills/ai-harness-eval/SKILL.md`: проверка поведения и отчёт.

Сверяй указанные пути с актуальным кодом. Не расширяй задачу ради рекомендаций для незатронутых модулей.

## Завершение

- Проверяй поведение соразмерно риску. После исправления повтори исходный сценарий; для существенной логики добавь целевую регрессионную проверку, когда это практически возможно.
- Линтер, сборка и проверка синтаксиса не заменяют проверку пользовательского сценария.
- Просмотри итоговый diff. Кратко сообщи результат, выполненные проверки и существенные ограничения; для недоступной проверки укажи конкретную причину.
