# Чек-лист проверки перед выдачей (Structured Cards V2 Validation)

Перед выдачей JSON-документа проверьте каждую карточку по этому списку:

## 1. Валидность JSON и схемы (`structured_cards_v2.py`)
- [ ] Корень документа содержит `"schema_version": 2` (число `2`), `"deck": {"name": "..."}` и непустой массив `"cards"`.
- [ ] Нет синтаксических ошибок JSON (нет комментариев, лишних запятых, `NaN`, дублирующихся ключей).
- [ ] Все `card.id` (если указаны) уникальны внутри документа.
- [ ] В объектах нет незарегистрированных полей (`extra="forbid"`).
- [ ] Все обязательные текстовые поля содержат хотя бы один непробельный символ.

## 2. Проверка по типам (`card.type` и `card.data`)
- [ ] **`"trainer"`**:
  - В `data.parts` есть хотя бы один элемент `"input"` или `"choice"`.
  - Пробелы и знаки препинания между пропусками сохранены в соседних элементах `{"type": "text", "text": "..."}`.
  - В `"input"` массив `answers` содержит уникальные строки без символов `[ ] { } | ; , / * _ \` < >` и переводов строк.
  - В `"choice"` минимум 2 варианта в `options`, все `text` уникальны, минимум один `"correct": true`, а неправильные варианты не совпадают с правильными после приведения к нижнему регистру.
- [ ] **`"quiz"`**:
  - В `data.options` минимум 2 варианта с уникальными `text`, и **ровно один** вариант имеет `"correct": true`.
  - Тексты `options` однострочные, не начинаются с маркеров списка (`-`, `•`, `A)`, `1.`) и не содержат `*`, `_`, `` ` ``.
- [ ] **`"match"`**:
  - В `data.pairs` минимум 2 пары `{"left": "...", "right": "..."}`.
  - В `left` и `right` нет переводов строк, разделителей `=>`, `->`, `—`, `=` и Markdown-символов `*`, `_`, `` ` ``.
- [ ] **`"puzzle"`**:
  - `data.tokens` — массив отдельных слов/токенов в **правильном** порядке (без пробелов внутри одного токена).
  - В `data.translation` указан перевод предложения.
- [ ] **`"word_bank"`**:
  - В `data.options` перечислены все слова банка (если одно и то же слово нужно вставить дважды — оно присутствует в `options` дважды под разными индексами).
  - В `data.parts` есть хотя бы один `{"type": "gap", "option": <index>}`, где каждый пропуск ссылается на свой уникальный индекс `0 <= option < len(options)`.
- [ ] **`"free_text"`**:
  - Заполнены `data.prompt` и непустой образец ответа `data.sample_answer`.
  - Тип использован для открытого высказывания или контролируемой трансформации предложения, а не для одиночного слова (для одного слова используйте `"trainer"`).
- [ ] **`"editable_text"`**: `source_text` содержит ошибку, `correct_text` — полное верное исправление; варианты равнозначны и ответ не раскрыт в `info`.
- [ ] **`"standard"`**:
  - Заполнены `data.prompt` и `data.answer`.
- [ ] **`"theory"`**:
  - Заполнен `data.text` (и при необходимости краткое резюме на обороте `data.summary`).

## 3. Педагогическое качество и отсутствие утечек ответа
- [ ] В `info` (`task`, `source`, `example`) и в видимом тексте задания нет подсказок, прямо выдающих правильный ответ.
- [ ] Поле `explanation` содержит содержательное пояснение правила и/или полный перевод фразы, а не пустую отписку.
- [ ] Уровень (`level`) и темы (`topics`) заданы в `deck.passport.intro` (без дублирования в карточках) либо явно на карточке (без запятых внутри названия темы).

## 4. Экономия токенов
- [ ] Опущены неиспользуемые поля (`id`, пустые `info`, `metadata`).
- [ ] Поля `level` и `topics` опущены в карточках, если они заданы в паспорте колоды.
- [ ] JSON компактен: нет широких 4-пробельных отступов и лишних пустых строк.
