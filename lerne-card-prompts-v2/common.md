# Общий контракт документа Structured Cards V2 (`schema_version: 2`)

## 1. Оболочка документа (`Document`)

Каждый документ описывает одну колоду (`deck`) и упорядоченный массив карточек (`cards`):

```json
{
  "schema_version": 2,
  "deck": {
    "name": "Plusquamperfekt: verstehen und üben",
    "passport": {
      "schema_version": 1,
      "intro": {
        "title": "Plusquamperfekt",
        "level": "B1",
        "topic": "Vorzeitigkeit",
        "goal": "Описывать действие, завершившееся до другого события в прошлом",
        "learning_outcomes": [
          "Выбирать вспомогательный глагол hatte или war",
          "Строить придаточные предложения с nachdem"
        ]
      },
      "pedagogy": {
        "lesson_type": "practice"
      }
    },
    "metadata": {
      "target_language": "de"
    }
  },
  "cards": [
    {
      "type": "trainer",
      "info": [
        {"type": "task", "text": "Ergänzen Sie das Hilfsverb im Plusquamperfekt."}
      ],
      "data": {
        "parts": [
          {"type": "text", "text": "Sie "},
          {"type": "input", "answers": ["hatte"]},
          {"type": "text", "text": " den Brief schon geschrieben."}
        ]
      },
      "explanation": "Она уже написала письмо. Глагол schreiben образует Plusquamperfekt с hatte."
    }
  ]
}
```

### Обязательные правила верхнего уровня:
- `"schema_version"` — строго целое число `2` (не строка `"2"`).
- `"deck.name"` — непустая строка с названием колоды.
- `"deck.passport"` — необязательный объект паспорта колоды по контракту [DECK_PASSPORT.md](../docs/DECK_PASSPORT.md). Если указаны `passport.intro.level` и `passport.intro.topic`, карточки наследуют их автоматически.
- `"cards"` — непустой массив карточек (от 1 до 1000).
- Неизвестные поля на любом уровне **запрещены** (`extra="forbid"`).

---

## 2. Общие поля карточки (`CardBase`)

| Поле | Тип | Обязательность | Назначение |
| :--- | :--- | :--- | :--- |
| `"type"` | `string` | **Обязательно** | Один из 9 типов: `"theory"`, `"standard"`, `"trainer"`, `"quiz"`, `"match"`, `"puzzle"`, `"word_bank"`, `"free_text"`, `"editable_text"`. |
| `"data"` | `object` | **Обязательно** | Данные конкретного типа карточки (см. `types/*.md`). |
| `"explanation"` | `string` | Необязательно (`""`) | Пояснение после ответа: перевод фразы + грамматическое правило. Компилируется в `CONTEXT`. |
| `"info"` | `array` | Необязательно | Информационные блоки (см. раздел 3). Если нет `task`/`source` — **опускайте**, не пишите `[]`. |
| `"id"` | `string \| null` | Необязательно | ID карточки. Для экономии токенов **опускайте**. |
| `"level"` | `"A1".."C2" \| null` | Необязательно | Если задан в `deck.passport.intro.level` — **опускайте** (наследуется). |
| `"topics"` | `string[] \| null` | Необязательно | Если задан в `deck.passport.intro.topic` — **опускайте** (наследуется). |
| `"metadata"` | `object` | Необязательно | Технические теги. Если нет — **опускайте**, не пишите `{}`. |

## 3. Информационные блоки (`card.info`)

Массив `"info"` задаёт блоки, которые ученик видит **над** интерактивным упражнением (в порядке следования):

1. **Инструкция к заданию (`"task"`)**:
   ```json
   {"type": "task", "text": "Ergänzen Sie die passende Verbform."}
   ```
2. **Исходный материал, контекст, перевод-подсказка или текст для чтения (`"source"`)**:
   ```json
   {"type": "source", "text": "Zuerst fuhr der Zug ab. Dann kamen wir am Bahnhof an."}
   ```
   *Правило:* Переводы отдельных слов или базовые формы глаголов (инфинитивы), которые раньше пытались писать в скобках прямо в предложении, выносите в `{"type": "source", ...}`, не раскрывая правильный ответ!
3. **Пример выполнения (`"example"`, можно несколько)**:
   ```json
   {"type": "example", "text": "gehen → ist gegangen"}
   ```
4. **Справочный список вариантов / слов (`"options"`)**:
   ```json
   {"type": "options", "items": ["ankommen", "abfahren", "umsteigen"]}
   ```
   *Внимание:* `info` с `"type": "options"` — это чисто информационная плашка. Для интерактивного банка слов (`"word_bank"`) рабочие варианты задаются внутри `data.options`.

## 4. Правила чистоты строк и совместимости с компилятором DSL

Документ V2 валидируется через `structured_cards_v2.py` и компилируется в DSL через `structured_cards_legacy.py` с проверкой round-trip. Чтобы компиляция проходила со 100% точностью:
- **Не используйте legacy-разметку внутри строк V2**: никаких `[[...]]`, `{...|...}`, `<<1>>`, `@puzzle`, `@match`, `@wordbank`, `@free`, `@edit`, `@theory`, `::task`, `::source`, `::exercise`, `::level`, `::topic`.
- **Без ведущих и хвостовых пробелов**: строковые значения (`answers`, `options`, `pairs`, `tokens`, `prompt`, `sample_answer`) не должны начинаться или заканчиваться пробелами/переводами строк; пробелы между словами при сборке `trainer` и `word_bank` хранятся в соседних элементах `{"type": "text", "text": " ... "}`.
- **Одна карточка — одна механика**: не пытайтесь смешать `quiz` и `match` в одной карточке. Единственное штатное совмещение — ввод (`input`) и выбор (`choice`) внутри единого типа `"trainer"`.
- **Экономия токенов**: не дробите текст в `trainer`/`word_bank` на мелкие кусочки без необходимости; объединяйте идущий подряд текст в один элемент `text`.

---

## 5. Правила экономии токенов (Token Efficiency)

1. **Наследование вместо дублирования**: указывайте `level` и `topic` один раз в `deck.passport.intro`. В объектах `cards` поля `level` и `topics` **не пишите** — они наследуются автоматически.
2. **Опускайте дефолтные поля**: не пишите `"id"`, пустые `"info": []`, `"metadata": {}`, `"accepted_answers": []`, `"summary": ""`.
3. **Компактный вывод**: форматируйте JSON плотно, без широких 4-пробельных отступов (1-2 пробела или компактные строки на карточку).
