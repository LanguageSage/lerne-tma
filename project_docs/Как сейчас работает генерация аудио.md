### 1. Как сейчас работает генерация аудио

Вся цепочка построена вокруг связки **React (TMA) $\to$ FastAPI $\to$ Edge TTS $\to$ Supabase / Local Storage**:

1. **Триггеры генерации**:
   - **Ручной режим (по клику / выбору голоса)**: в раскрытом плеере карточки пользователь выбирает голос $\to$ отправляется запрос на `/api/media/generate-audio` (генерируется временное превью в памяти/кеше, карточка в БД не затирается). Если нажимается «Перезаписать» $\to$ вызывается `/api/media/generate-card-audio`, файл сохраняется в БД карточки, а старый отвязавшийся файл очищается.
   - **Самовосстановление (Self-healing)**: если у карточки поврежден или отсутствует аудиофайл (ошибка 404/decode), плеер перехватывает это через `onPlaybackError`, крутит спиннер на кнопке Play, тихо отправляет генерацию на бэкенд, обновляет путь к карточке в БД и сразу начинает воспроизведение без панических тостов.
   - **Авторежим (useAutoplay)**: использует **упреждающий фоновый префетч**:
     - Пока звучит лицевая сторона (`front`) карточки, в фоне тихо генерируется озвучка перевода (`back`).
     - Пока звучит перевод, заранее генерируется озвучка лицевой стороны *следующей* карточки из очереди. Паузы между карточками сведены к минимуму.

2. **На бэкенде (`api/utils/audio.py` и `/api/routers/media.py`)**:
   - Очищается текст фразы (убираются служебные пометки/скобки).
   - Вычисляется MD5-хеш от комбинации `(clean_text, voice, rate)`.
   - Если файл с таким хешем уже есть на диске — бэкенд возвращает его мгновенно (Fast path).
   - Если нет — вызывается `edge-tts.Communicate`, стрим байтов пишется в `user_files/pending_audio/` (параллельно снимаются тайминги `word_boundaries` для караоке).
   - При наличии конфигурации Supabase файл асинхронно выгружается в облачный бакет, а ссылка сохраняется в БД.

### 2. К каким выводам пришли по результатам ревизии

1. **Пользовательский опыт (UX) стал чистым и бесшовным**:
   - Пользователь больше не видит красных тостов «Файл поврежден или отсутствует» — интерфейс просто тихо чинит озвучку и воспроизводит её.
   - Свернутый плеер теперь ультра-компактный: только `Play/Pause`, переключатель скорости (`1.0x`) и кнопка настроек/разворота (`⚙`).
   - Смена голоса в плеере больше не ломает колоду и не перезаписывает базу вслепую — есть четкое разделение «Прослушать» (превью) и «Перезаписать» (сохранение в карточку).
2. **Экономия ресурсов и порядок в БД**:
   - Перевод (`back`) больше не генерируется вхолостую при ручном изучении карточек или их создании (только по требованию или в режиме «Авто»).
   - Устранены дублирующие вызовы и лишние перерисовки в React-хуках, почищены неэффективные динамические импорты (сборка фронтенда стала чистой, 0 ошибок линтера, сборка 1.1 секунды).

### 3. Как можно улучшить дальше (перспективы и точки роста)

1. **Кеширование аудио на клиенте (IndexedDB / Cache API)**:
   - *Сейчас:* браузер скачивает аудиофайл по URL каждый раз при открытии (или полагается на стандартный HTTP-кеш браузера).
   - *Улучшение:* кешировать воспроизведенные аудио-блобы в локальной базе Dexie / Cache API. Это позволит карточкам звучать мгновенно даже в Telegram при плохом 3G-интернете или в офлайне (полный Offline-first).

2. **Очередь генерации на бэкенде (Celery / BackgroundTasks / Async Limiter)**:
   - *Сейчас:* если пользователь быстро листает режим авто или импортирует колоду на 50 карточек, уходит пачка параллельных вызовов к серверам Microsoft Edge TTS. При лимитах Edge TTS может временно троттлить (429 Too Many Requests).
   - *Улучшение:* добавить простой асинхронный семафор (например, `asyncio.Semaphore(3)` на бэкенде), чтобы одновременно шло не более 2–3 параллельных генераций Edge TTS.

3. **Фоновая очистка неиспользуемых аудиофайлов (Garbage Collection)**:
   - *Сейчас:* при перезаписи старый файл удаляется, но временные превью (`pending_audio`) со временем могут накапливаться на диске сервера.
   - *Улучшение:* настроить cron/фоновую задачу раз в неделю, удаляющую файлы из `pending_audio`, к которым не обращались более 7 дней и которых нет в записях `tma_card.audio_path`.

4. **Интеллектуальная предгенерация колоды при создании/импорте**:
   - При создании новой колоды или генерации через AI запускать единый пакетный воркер генерации аудио в фоне (с низкой приоритетностью), чтобы к моменту первого открытия колоды все карточки уже имели готовый аудиофайл.
