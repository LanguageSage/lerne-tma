Нумерация карточек в приложении работает по следующему принципу:

### 1. Хранение в базе данных (`position`)
- В таблице `tma_card` у каждой карточки есть поле **`position`** (целое число от `0` до `N-1`).
- При загрузке карточки всегда сортируются по правилу:  
  **`order_by(position.asc(), id.asc())`**  
  *(если позиции равны, порядок страхуется по ID создания)*.

---

### 2. Отображение в интерфейсе (1-based)
- Пользователь видит нумерацию, начинающуюся с единицы:  
  $$\text{Отображаемый номер} = \text{Индекс в отсортированном списке} + 1$$
- Карточка на 0-м месте показывается как **№ 1**, на 1-м — как **№ 2** и так далее.
- В **сквозном поиске** сервер заранее вычисляет точный порядковый номер карточки именно внутри её колоды (`card_number`), поэтому номер совпадает везде.

---

### 3. Что происходит при изменении порядка (Drag & Drop или ручной номер)
1. **Сдвиг в памяти (`arrayMove`)**:  
   Карточка вынимается из старой позиции и вставляется на новую. Карточки в промежутке аккуратно сдвигаются на **`+1`** (или **`-1`**), сохраняя свой относительный порядок.
2. **Переприсвоение позиций**:  
   Всему списку карточек колоды подряд назначаются новые позиции: `0, 1, 2, 3 ... N-1`.
3. **Синхронизация**:  
   - Мгновенно обновляется экран (оптимистичный UI);
   - Сохраняется в локальную память устройства (Dexie / IndexedDB для офлайна);
   - Отправляется на сервер в `/api/cards/reorder`, где в одной транзакции база данных перезаписывает `position` для всех карточек этой колоды. Никаких пропусков номеров или дубликатов не возникает.
