# Лог Принятых Решений (Decisions Log)

В данном документе фиксируются основные архитектурные, инженерные и UX решения с датами, контекстом, обоснованием и результатом.

## 📅 Хронология ключевых решений

### 🟢 11 Августа 2026: Защита выбора языка через Telegram CloudStorage + Supabase DB
- **Контекст**: В браузере от Telegram (iOS/Android WebKit) при закрытии Mini App стирался `LocalStorage`, из-за чего приложение каждый раз заново показывало окно выбора языка.
- **Принятое решение**:
  1. Внедрена работа с **Telegram CloudStorage API** (`cloudStorage.set/get`) для дублирования настроек в облако Telegram аккаунта.
  2. Добавлены колонки `active_language` и `has_selected_language` в таблицу `tma_user` в Supabase DB.
  3. Реализована каскадная инициализация: при старте язык восстанавливается из LocalStorage → CloudStorage → Supabase DB.
- **Результат**: Окно выбора языка гарантированно всплывает 1 раз при самом первом входе и больше никогда не беспокоит пользователя.

---

### 🟢 25 Июля 2026: Миграция с SQLite на PostgreSQL (Supabase Cloud) + Ленивая инициализация
- **Контекст**: Локальный SQLite файл при деплое на Vercel терял таблицы (`no such table: tma_folder`), так как Vercel функции работают в read-only файловой системе.
- **Принятое решение**:
  1. Перевод проекта на PostgreSQL (Supabase).
  2. Внедрение гибридной системы драйверов: `psycopg2-binary` как основной и `pg8000` (чистый Python) как fallback для бессерверной среды.
  3. Перевод `initialize_database()` на ленивый режим без принудительного открытия TCP соединения при импорте модулей, чтобы не возникало таймаутов на "холодном старте" Vercel.
- **Результат**: Стабильная работа API на Vercel с реактивным доступом к областной БД Supabase.

### 🟢 20 Июля 2026: Изоляция контента по языкам обучения (`target_language`)
- **Контекст**: Колодки и папки немецкого, английского и норвежского языков перемешивались на одном экране.
- **Принятое решение**:
  1. Добавление колонки `target_language` для `tma_deck`, `tma_folder`, `tma_custom_prompt`.
  2. Фильтрация данных на уровне SQL-запросов и сервисов.
  3. Автоматический перезапрос данных колод при смене активного языка в UI.
- **Результат**: Каждое языковое пространство (DE 🇩🇪, EN 🇬🇧, NO 🇳🇴) стало изолированным и чисто структурированным.

---

### 🟢 15 Июля 2026: Оптимизация Инициализации через Эндпоинт `/api/init`
- **Контекст**: При запуске приложения фронтенд делал 4 отдельных HTTP запроса (за колодами, папками, настройками и промптами), создавая задержки на мобильных сетях.
- **Принятое решение**: Создание единого консолидированного эндпоинта `/api/init`, отдающего колоды, папки, настройки и промпты в 1 пакетном запросе.
- **Результат**: Ускорение загрузки приложения на 70%.

---

### 🟢 10 Июня 2026: Автономная система интервальных повторений SM-2 и Индексация
- **Контекст**: Требовалось реализовать эффективный подсчет карточек на повторение без нагрузки на сервер.
- **Принятое решение**:
  1. Реализована классическая схема SuperMemo-2 (`ease_factor`, `interval`, `repetitions`).
  2. Добавлены составные индексы в PostgreSQL (`idx_tma_card_deck_deleted`, `idx_tmaprogress_queue_review`).
- **Результат**: Выборка карточек на повторение происходит за <5 мс даже при десятках тысяч карточек.
