## Поведение и настройки

Ручное завершение — режим по умолчанию для нового пользователя. После включения
голоса действует существующий цикл: при включённом автоозвучивании сначала
озвучивается последняя реплика NPC, затем включается микрофон. Кнопку удерживать
не нужно. Паузы и нативные завершения отдельных сессий браузера не отправляют
реплику. «Завершить реплику» вызывает `stop()`, принимает оставшиеся финальные
результаты и отправляет завершённый текст один раз. Нажатие во время промежутка
между сессиями тоже работает. Если текст всё ещё промежуточный, имеет низкую
confidence, не содержит букв или длиннее 1000 символов, нужна проверка текста и
явная кнопка «Отправить». Отсутствующая confidence (0) не считается низкой оценкой.

Автоматический режим включается через «Отправлять после паузы». Доступны 2, 3, 4,
5 секунд; начальное значение — 4 секунды. Промежуточные и финальные результаты
обновляют таймер; начало речи снимает его, окончание речи ставит заново. Нативный
`onend` не завершает реплику и не сбрасывает её оставшийся тайм-аут. Через 350 мс
создаётся новая сессия. На каждом событии берётся актуальный снимок `results`
сессии: повторные cumulative events и замена interim на final не дописывают
текст второй раз. Намеренные повторы вроде «Ja, ja» сохраняются. Неокончательный
фрагмент из завершившейся сессии сохраняется для проверки, если последующий
результат не заменяет его полной финальной фразой. Несвязанные interim-фрагменты
не отправляются автоматически и не исчезают незаметно.

| Настройка | Хранение | Начальное значение |
| --- | --- | --- |
| Автоматическая отправка | `lerne_game_auto_send` в localStorage | false; ранее явно сохранённый выбор учитывается |
| Пауза | `lerne_game_silence_seconds` в localStorage | 4; допустимы 2/3/4/5 |
| Автоозвучивание | существующий `lerne_game_autoplay` | true |
| Включённый микрофон | только текущий runtime | выключен после перезагрузки |
| Голос NPC | существующий `npc.tts_voice` | `de-DE-KatjaNeural` |

«Пауза» и выключение голоса сохраняют черновик; «Отменить реплику» очищает его и
останавливает распознавание. Фокус текстового ввода переводит разговор на текст.
Изменение режима/тайм-аута приостанавливает слушание; при наличии черновика его
можно проверить и отправить либо отменить. Hide, Back, новый диалог, unmount,
пауза и выключение отменяют recognition, таймеры, TTS HTTP и аудио. Поколение
реплики и принадлежность callback текущему recognizer защищают от поздних событий.
Существующий request_id/version и блокировка отправки сохранены.

Ресурсные пределы: permission 30 с, первоначальное пустое ожидание 45 с,
финализация `stop()` 3 с. После появления текста пустой watchdog снимается;
пауза внутри ручной реплики сама по себе не ограничена 45 секундами. Пять
последовательных пустых нативных сессий приостанавливают слушание. `no-speech`
обрабатывается через последующее `onend`; ошибки доступа/сети требуют явного
продолжения, сохраняя текст.

## Свободный разговор и серверный каталог

`npc` — постоянный паспорт: имя, возраст, профессия, характер, знания, привычки,
манера речи, постоянный голос и правила персонажа. Сюжетное направление находится
отдельно в `scene.suggested_topic`; `target_book_id` нужен серверу для определения
результата выдачи. Общий системный промпт использует эту границу для любого NPC:
сюжет предлагает цель, но не диктует содержание разговора. Он разрешает смену темы,
разговор о жизни, работе, автомобилях и обычном опыте персонажа, а также возврат по
инициативе пользователя. Запрещены выдуманные факты мира, изменение каталога,
навязывание задачи, постоянные похвалы, повторение отвеченных вопросов и поведение
универсального ИИ-ассистента. Персонаж может признать нехватку знаний.

В формулирование ответа передаются паспорт, необязательное направление, факты
мира, событие, история и `simple_language`. Незавершённые критерии поиска и outcome
больше не передаются как состояние для обычного ответа. Интерпретатор по-прежнему
видит критерии для понимания явных продолжений поиска; chat не меняет их и не
выдаёт книгу. Тема книги больше не ограничена тремя категориями: ограниченная
строка, например `automotive`, даёт серверный `not_found`, если совпадений в
каталоге нет. Предыдущее предложение книги очищается; подтверждение не может
выдать книгу на основании старого предложения. Каталог не расширяется.

UI называет сюжет «Возможная цель разговора» и прямо разрешает выбор темы.
Получение другой книги не сопровождается указанием обязательно повторить задачу.
Правила авторизации, доступности, выдачи, одного займа на попытку, лимиты и
результаты `ongoing/success/other_book` остаются прежними.

## Ограничения и ручная проверка

`continuous=true` запрашивает последовательные результаты, но не гарантирует
непрерывное распознавание или поддержку на всех браузерах. Сессии могут завершаться
самостоятельно; во время 350-мс перезапуска слова могут потеряться, а браузер может
отказать в повторном старте. Приложение показывает это ограничение и сохраняет
текст для проверки. Автопауза определяется событиями STT, а не собственной записью
аудио: это не точный акустический VAD. Если после `stop()` final не получен,
доступна ручная проверка; Lerne не дополняет незавершённую фразу догадкой.

Источники: [Web Speech API — continuous](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/continuous),
[массив final/interim результатов](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognitionEvent/results).
Некоторые браузеры отправляют аудио своему сервису; Lerne не сохраняет raw recording.

Настоящий микрофон, распознавание немецкого, реальное Edge TTS, эхо, мобильный
autoplay и естественность ответов выбранного live AI автоматически не проверены.
Backend dialogue tests проверяют маршрутизацию, контекст и серверную защиту с
подменённым AI, а не качество реальной модели.

Для финальной акустической проверки в целевом Chrome/мобильном браузере:

1. В live Game Mode включить голос, дать разрешение, дождаться окончания речи NPC.
   В ручном режиме сказать «Ich möchte … ein Buch … über Autos», сделав несколько
   пауз 2–6 с. Проверить сохранение текста без отправки; нажать завершение один раз.
2. Повторить в автоматическом режиме сначала с 2, затем с 5 с, в том числе с
   промежуточными результатами, молчанием, шумом и коротким «Ja».
3. Отменить фразу, выключить микрофон, отредактировать текст, скрыть вкладку и уйти
   назад: аудио и микрофон должны остановиться без поздней отправки.
4. После начала поиска балконной книги спросить о машинах и работе библиотекаря.
   Попросить книгу по ремонту автомобилей: NPC сообщает только факт отсутствия
   подходящей книги. Затем самому вернуться к балконной теме и получить серверное
   предложение. Подтвердить его и проверить прежнюю выдачу.


## Дополнение: накопление промежуточных гипотез

Сообщённая пользователем цепочка точно воспроизведена в тесте следующим
форматом событий: внутри `results` находятся растущие версии всей фразы в разных
слотах — «guten», «guten Tag», «guten Tag ich suche», «guten Tag ich suche ein Buch».
Проверены варианты с interim и `isFinal=true`. Сырые события реального устройства
не получены, поэтому их формат остаётся предположением. Простого обновления снимка
сессии недостаточно для такого формата: склейка его элементов давала те же повторы.

В `useGameVoice.js` добавлена единая сборка `speechFragments` для отображения,
черновика, проверки окончательности и отправки. Она сравнивает полные слова без
учёта регистра/пунктуации, сворачивает последовательные растущие interim-гипотезы
до последней и умеет заменить незавершённую гипотезу после перезапуска сессии.
Уже подтверждённый фрагмент перед новой interim-гипотезой сохраняется. Для цепочки
только из final-фрагментов нужны хотя бы два расширения префикса; равные final
сегменты без расширения остаются отдельными. «Ja ja», «sehr sehr gut», повторное
«Guten Tag», независимые фрагменты и разные слова «Buch/Bücher» не удаляются
глобальным фильтром повторяющихся слов.

Для нестандартных all-final цепочек это эвристика: намеренный повтор последовательных
всё более длинных одинаково начинающихся фраз нельзя без аудио безошибочно отличить
от накопленных гипотез движка. Реальная работа микрофона на устройстве пользователя
остаётся ручной проверкой; автоматический тест воспроизводит переданные STT события.

В браузерные тесты добавлены пять регрессий: сообщённая фраза с interim и final
цепочками, гипотезы через перезапуски и автоотправка один раз, настоящие final
повторы и сохранение финального слова перед промежуточным повтором. Перед
исправлением первые два теста падали с той же цепочкой дубликатов.

Backend, настройки NPC, БД и MVP 3 в этом исправлении не менялись. Commit/push
