# Lerne TMA: Справочник Архитектуры и Карта Ключевых Функций

> **Цель документа**: Дать вам (разработчику и автору идей) полную картину работы приложения без необходимости учить код и синтаксис. Используйте этот справочник, чтобы формулировать точные и экономичные задачи для ИИ.

---

## 1. Как давать ИИ точечные команды (Шпаргалка разработчика)

Вам **не нужно** писать код или помнить названия всех переменных. Ваша задача как архитектора — сказать ИИ **«Что сделать»**, **«В каком файле/сервисе»** и **«Какую функцию использовать»**.

### Плохой промпт (тратит много токенов и создает баги):
> *«Сделай так, чтобы после карточки показывался новый интервал и чтобы все работало быстрее.»*

### Хороший точечный промпт (быстро, дешево, без багов):
> *«Посмотри в `api/srs.py` на функцию `review_card`. Добавь логику, чтобы при 8-балльной оценке вычислялся дополнительный бонус к `ease_factor`. Изменения в UI сделай в `StudyView.jsx`.»*

## 2. Карта Бэкенда (Python / FastAPI)

### 🧠 Обучение и SRS (Интервальное повторение)
| Файл | Ключевая функция | Что делает простыми словами |
| :--- | :--- | :--- |
| `api/srs.py` | `review_card(progress, grade)` | Главный мозг SRS. Принимает оценку пользователя (0-7) и высчитывает дату следующего показа карточки (`next_review`) и фактор легкости (`ease_factor`). |
| `api/srs.py` | `get_next_intervals(progress)` | Возвращает подписи для кнопок повторения (например: «10 мин», «1 дн», «4 дн»). |
| `api/srs.py` | `apply_fuzz(interval)` | Размывает интервал на +-5-10%, чтобы карточки не копились «кучей» в один день. |
| `api/services/study.py` | `get_next_study_card(...)` | Выбирает из базы следующую карточку для сессии обучения (учитывая приоритеты new/learning/review). |

## 3. Карта Фронтенда (React / Zustand / Dexie)

Фронтенд состоит из **Сторов (Stores)**, которые хранят состояние в памяти, и **Компонентов (UI)**, которые отображают интерфейс.

### 💾 Сторы состояния (`app/src/store/`)
| Стор / Файл | Ключевой метод / Поле | Что делает простыми словами |
| :--- | :--- | :--- |
| `useDeckStore.js` | `decks`, `folders`, `fetchDecks()` | Держит в памяти список всех колод и папок. Обновляет UI при их изменении. |
| `useSessionStore.js` | `currentCard`, `submitAnswer(grade)` | Управляет активным экраном обучения: какая карточка сейчас на экране, сколько осталось, отправка ответа. |
| `useAuthStore.js` | `user`, `token`, `login()`, `logout()` | Хранит токен авторизации и профиль текущего пользователя. |
| `useSettingsStore.js` | `settings`, `updateSetting()` | Настройки пользователя (тема, режим кнопок SRS 4/8, авто-озвучка). |
| `useUiStore.js` | `activeModal`, `openModal()`, `closeModal()` | Управляет открытыми всплывающими окнами (модалками). |

---

### 📦 Офлайн Хранилище (`app/src/services/` & `utils/`)
| Файл | Ключевая функция | Что делает простыми словами |
| :--- | :--- | :--- |
| `localDb.js` | `db.cards`, `db.decks` (Dexie.js) | Локальная база данных прямо в браузере/Telegram. Позволяет учить карточки без интернета. |
| `offlineApi.js` | `saveCardOffline(...)` | Сохраняет измененную карточку сначала в `localDb`, а затем ставит запрос в очередь синхронизации. |

## 4. Практический тренажер: Проектируем фичу «Соревнование / Игра»

Представим, что вы хотите внедрить новую идею: **Совместная дуэль по карточкам (PvP)**.

### Шаг 1: Разбор по слоям (Как мыслить архитектору)
1. **Бэкенд Сервис (`api/services/game_service.py`)**: Нужна функция `create_room(user_id)` и `process_turn(room_id, user_id, is_correct)`.
2. **Бэкенд Роутер (`api/routers/game.py`)**: Эндпоинты `/api/game/create` и WebSocket `/ws/game/{room_id}` для мгновенного обмена очками.
3. **Фронтенд Стор (`app/src/store/useGameStore.js`)**: Поля `roomCode`, `opponentScore`, `myScore`, `status`.
4. **Фронтенд UI (`app/src/components/game/GameRoom.jsx`)**: Визуальный дуэльный экран с прогресс-барами игроков.

### Шаг 2: Ваша готовая команда для ИИ
> *«ИИ, я хочу добавить соревновательный режим. Создай новый стор `useGameStore.js` на фронтенде для хранения счета дуэли, и создай сервис `api/services/game_service.py` с функцией `process_turn`, которая будет начислять очки за скорость. Используй структуры данных по аналогии с `useSessionStore.js`.»*

## 5. Главные правила сохранения ресурса токенов

1. **Не просите менять несколько слоев сразу без плана**: Сначала попросите сделать Бэкенд-сервис, проверьте его, а затем переходите к UI.
2. **Используйте ссылки на эти файлы**: Когда даете задачу, пишите: *«Используй паттерн из `api/srs.py`»*. ИИ сразу поймет стиль без длинных объяснений.
3. **Обновляйте этот документ при добавлении крупных модулей**.
