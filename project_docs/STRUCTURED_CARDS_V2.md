# Структурированные карточки V2 — этапы 1–5

V2 — JSON для авторства человеком и ИИ. Тип задан явно; ответы и данные упражнения
не извлекаются из FRONT. Это отдельный контракт и инструмент предварительной
проверки: действующие импорт ученика, учебный UI, БД, синхронизация и уроки его пока не используют.
В «Авторе уроков» доступен отдельный предварительный просмотр JSON V2 без сохранения.
Реализован также этап 1 [плана нативного хранения](STRUCTURED_CARDS_V2_ARCHITECTURE.md#реализация-этапа-1):
single-card validation, строгие save/read envelopes, каноническая нормализация и
display/search projection с отдельным наследованием паспорта. Это чистые контракты;
сохранение, маршруты API, sync и учебный runtime ещё не подключены.

## Что обнаружено в действующей архитектуре

| Путь | Владелец и ограничения |
| --- | --- |
| Редактор → сохранение | `cardData.front` → `/cards/save` → `TMA_Card.front_text`; offline — Dexie. `back_text`, `context`, `topics`, `metadata` — отдельные поля. |
| Быстрый импорт | `app/src/utils/batchCardParser.js`: секции FRONT/BACK/CONTEXT, затем информационные блоки и определение типа по FRONT. Может достраивать BACK и уровень по умолчанию. |
| «Автор» / CLI | `api/services/author_service.py`: документ с колодами и паспортами, наследование уровня/темы, существующий bulk-save. Это отдельный путь от быстрого импорта ученика. |
| Граница текста и информации | `exerciseContentParser.js` и `input_parser.py`: task/source/example/options, exercise и маркер Theory. `source` не равен CONTEXT. |
| Упражнения | `exerciseDetector.js`, `clozeParser.js`, `quizParser.js`, `matchParser.js`, `wordBankParser.js`, `freeTextParser.js`; Puzzle собирается в `StudyCardPuzzle.jsx`. |
| Проверка | `trainerEvaluation.js` принимает варианты ответа через `\|`; `answer_contract.py` владеет политикой проверки открытого ответа. |

Тип в legacy не является надёжным источником: frontend и backend повторно
определяют его по тексту, причём приоритеты Quiz/Trainer различаются. Поэтому
конвертер проверяет совместимость и отказывает при неоднозначности.

## Документ

```json
{
  "schema_version": 2,
  "deck": {"name": "Немецкий: прошлое"},
  "cards": [{
    "id": "past-mixed-1",
    "type": "trainer",
    "info": [{"type": "task", "text": "Ergänzen Sie den Satz."}],
    "data": {
      "parts": [
        {"type": "choice", "options": [
          {"text": "Als", "correct": true}, {"text": "Wenn"}
        ]},
        {"type": "text", "text": " ich ankam, "},
        {"type": "input", "answers": ["hatte"]},
        {"type": "text", "text": " sie schon gegessen."}
      ]
    },
    "explanation": "Als — однократное событие в прошлом."
  }]
}
```

Один документ описывает одну колоду и непустой список карточек в учебном порядке.
Обязательны `schema_version`, `deck.name`, `cards`, `card.type`, `card.data`.
`schema_version` — целое `2`; неизвестные поля и типы запрещены, значения не
приводятся автоматически из строк/чисел/bool. Пустой обязательный текст запрещён.
Строки содержат обычный текст/Markdown; маркеры legacy не имеют специального
значения в V2. Никакого шаблона `{{gap}}` и повторного разбора строки не требуется.

Общие необязательные поля карточки:

| Поле | Значение |
| --- | --- |
| `id` | Непустая строка, уникальная внутри документа; авторская ссылка, не ID записи БД. |
| `info` | Упорядоченные информационные блоки перед упражнением: `{type: task/source/example, text}` либо `{type: options, items: [...]}`. Блоки можно повторять. Их текст не определяет тип карточки. |
| `explanation` | Пояснение после ответа, соответствует legacy CONTEXT, по умолчанию `""`. |
| `level` | CEFR A1–C2; отсутствие или null наследует `passport.intro.level`. |
| `topics` | Массив непустых строк; отсутствие или null наследует `[passport.intro.topic]`, `[]` явно снимает темы. |
| `metadata` | JSON-объект расширений: происхождение, теги, авторские заметки. Не место для второго экземпляра содержимого/ответов. |

Уровень и темы наследуются независимо. При отсутствии значения и в карточке,
и в паспорте конвертер возвращает `level: null`, `topics: ""`, без выдуманного A1.
Поле `deck.metadata` также хранит дополнительные метаданные, например язык.
Служебные поля содержимого, уровня, ответов и паспорта запрещены непосредственно
в metadata; SRS и история обучения не входят в формат авторства.

## Данные всех типов

| `type` | Обязательные данные в `data` | Ответ / дополнительные данные |
| --- | --- | --- |
| `theory` | `text` | Необязательный `summary` — оборот карточки, по умолчанию пустой. Примеры с пропусками в тексте остаются теорией. |
| `standard` | `prompt`, `answer` | Текст вопроса и оборот. |
| `trainer` | `parts` | Последовательность text/input/choice, минимум один пропуск. Режим определяется каждым пропуском, смешанный Trainer не требует отдельного типа. |
| `quiz` | `prompt`, `options` | Минимум два `{text, correct?}`. `correct` по умолчанию false, минимум один true; несколько правильных допустимы в контракте V2. |
| `match` | `pairs: [{left, right}, ...]` | Минимум две пары. Пары и их порядок сохраняются, включая повторы. В legacy каждый правый элемент расходуется один раз; одинаковые значения справа (после нормализации пробелов) взаимозаменяемы. |
| `puzzle` | `tokens: ["Ich", "bin", "angekommen."]` | Непустой массив токенов в правильном порядке. Повторы допустимы, идентичные токены различаются позицией. Необязательный `translation`. |
| `word_bank` | `options: ["habe", "bin", ...]`, `parts` | text либо `{type: "gap", option: 0}`. `option` — индекс правильного элемента options с нуля, один элемент расходуется один раз. Повторяющиеся слова задаются отдельными элементами, неиспользуемые — дистракторы. |
| `free_text` | `prompt`, `sample_answer` | Образец не является точным ключом. Необязательные `accepted_answers`, `grading_policy` используют действующий контракт. При отсутствии политики используется `mode: open_text`. |

Trainer: `{type: "text", text: "..."}`, `{type: "input", answers: ["hatte"]}`,
`{type: "choice", options: [{text: "war", correct: true}, {text: "hatte"}]}`.
`answers` — непустой список уникальных допустимых ответов. В choice допустимы
несколько correct; тексты вариантов уникальны. Пробелы задаются явно в text-частях,
включая отдельную строку `" "`; пропуск может быть частью слова. Ответ хранится
только в своём пропуске, отдельного редактируемого BACK Trainer нет.

## Паспорт и владение данными

`deck.passport` принимает существующий объект `{schema_version: 1, intro?, pedagogy?}`.
Его валидирует `api/services/deck_passport.py`; правила паспорта не копируются.
Диапазоны этапов дополнительно проверяются относительно числа карточек V2.
Версия паспорта независима от версии карточек. Подробнее: [DECK_PASSPORT](../docs/DECK_PASSPORT.md).

**Единственный источник истины** нового документа — его `type`, `data`, `info`,
`explanation` и явные метаданные. FRONT/BACK — одноразовая производная проекция.
Существующие карточки продолжают иметь прежний источник истины. Не следует
записывать V2 в metadata старой карточки вместе с независимо редактируемым FRONT.

## Реализация и запуск

- `api/services/structured_cards_v2.py`: строгие Pydantic-модели всех типов,
  `validate_document(dict)`, `load_document(json_text)` и генерируемая JSON Schema.
- `api/services/structured_cards_legacy.py`: `to_legacy_document(dict | Document)`
  для всех восьми типов (Quiz — с одним правильным ответом).
- `scripts/structured_cards_v2.py`: отдельный CLI, только чтение файла и stdout.
  Перед API-import отключает прежнюю инициализацию таблиц, как `lesson_qa.py`.

Из корня проекта, Python с существующими зависимостями API (в Windows можно
использовать `venv\Scripts\python.exe`):

```powershell
python scripts/structured_cards_v2.py validate project_docs/examples/structured_cards_v2/basics.json
python scripts/structured_cards_v2.py to-legacy project_docs/examples/structured_cards_v2/basics.json
python scripts/structured_cards_v2.py to-legacy project_docs/examples/structured_cards_v2/match.json
python scripts/structured_cards_v2.py to-legacy project_docs/examples/structured_cards_v2/puzzle_quiz.json
python scripts/structured_cards_v2.py to-legacy project_docs/examples/structured_cards_v2/word_bank_free_text.json
python scripts/structured_cards_v2.py schema
python -m unittest scripts.tests.test_structured_cards_v2 -v
```

JSON с повторными ключами, NaN/Infinity, ошибками схемы или паспорта отклоняется;
ошибки схемы содержат пути полей. CLI возвращает exit code 1 при ошибке.
JSON Schema строится из моделей, отдельной копии схемы нет. Дополнительные
семантические проверки (ссылки, уникальность, паспорт) выполняет валидатор Python.

Результат преобразования — `{deck, cards}` для просмотра/будущего адаптера,
**не готовый запрос сохранения** и не текстовый файл «Автора». Паспорт остаётся
в deck; `source_id` сохраняет авторскую ссылку и не используется как `card_id`.
BACK Trainer строится из ответов, объяснение переносится в CONTEXT; topics
преобразуются в существующую строку. Вход не изменяется, частичный результат
при ошибке не возвращается. Проверяются текущие границы информационных блоков.

Все восемь типов имеют legacy-проекцию и проверку совместимости.
Quiz с несколькими правильными ответами валиден V2, но не представим этой legacy-проекцией.
Литеральные маркеры V2, скобки в тексте Trainer, Markdown/разделители в ответах
и другие случаи, которые legacy исказит, также отклоняются с путём карточки.
Значения тем с запятыми/переносами строк не склеиваются молча. Правила проверки
ответов в этом адаптере остаются действующими правилами legacy; варианты,
которые после нормализации сделают дистрактор правильным, отклоняются.

Готовые учебные примеры: [basics.json](examples/structured_cards_v2/basics.json)
(Theory, Standard, ввод, выбор, смешанный Trainer) и
[other_types.json](examples/structured_cards_v2/other_types.json)
(Quiz, Match, Puzzle, Word Bank, Free Text); [match.json](examples/structured_cards_v2/match.json)
содержит отдельный конвертируемый Match с повторяющимися правыми значениями и парами.
[puzzle_quiz.json](examples/structured_cards_v2/puzzle_quiz.json) — конвертируемые Puzzle
с повторениями и пунктуацией и Quiz с одним правильным вариантом.
[word_bank_free_text.json](examples/structured_cards_v2/word_bank_free_text.json) содержит
Word Bank с двумя копиями habe, дистракторами и пропусками в порядке 2/3/1,
а также Free Text в режимах open_text, controlled_text и exact.
Файл other_types валиден V2; конвертация всего документа завершается ошибкой
из-за Quiz с несколькими правильными ответами.

Проверки: `scripts/tests/test_structured_cards_v2.py`; мост
`tools/structured_cards_v2_compat.mjs` передаёт проекцию настоящим frontend
parser/detector/evaluator, проверяет правильные ответы, дистракторы, альтернативы,
окончание внутри слова и информационные блоки. Match проверяется через действующие
`matchParser.js` и `matchEvaluation.js`: точное равенство пар, порядок/повторы,
матрица правильных/неправильных связей, полное завершение и расходование правых элементов.
Тесты не сохраняют карточки.

## Следующие минимальные этапы

Техническое решение следующего этапа:
[Нативное хранение и редактирование V2](STRUCTURED_CARDS_V2_ARCHITECTURE.md).
Документ фиксирует отдельное JSON-поле существующей карточки, явную версию,
защиту ревизией, контракт редактирования, совместимость старых клиентов,
offline/sync, риски и независимо проверяемые этапы внедрения. Это план, а не
уже действующие API/БД/UI.

Первый безопасный этап — чистые контракты single-card storage/wire и производные
представления с изолированными тестами, без сохранения и миграций. Затем —
неактивная схема, защита всех путей записи, полное чтение/backup, доставка,
нативный runtime, импорт и редактор. Старые карточки продолжают работать;
массовая миграция и удаление legacy не являются условием нативного хранения.
Обратный legacy → V2 конвертер отсутствует: угадывание структуры существующих
уроков требует отдельного аудита и явного preview.

## Этап 2: preview в «Авторе уроков»

Вкладка **JSON V2 · Preview** принимает один `.json` (UTF-8, в том числе BOM,
до 10 МБ) через `POST /api/admin/author/v2-preview`. Существующий `load_document`
остаётся единственным загрузчиком/валидатором. Ответ содержит `valid`, `errors`;
при успехе — нормализованный `document`, `total_cards`, `types`, `legacy_projections`.
Ошибки содержат путь JSON `cards[1].data.answer` (индексы с нуля) и
`card_number` с единицы; синтаксические ошибки JSON — строку и столбец.
Невалидный документ не конвертируется. Ограничения файла возвращают HTTP 400/413.

Показаны паспорт, все восемь типов, информационные блоки, ответы и объяснения.
HTML/Markdown отображается обычным экранированным текстом, без исполнения HTML,
загрузки пользовательских ресурсов или повторного разбора legacy-маркеров.
Для Free Text образец явно отделён от точного ключа, политика проверки сохранена.
Полные данные карточки доступны отдельно от временной legacy-проекции.

Существующий алгоритм конвертера открыт как `to_legacy_card` для **уже
валидированных** моделей карточки/колоды; `to_legacy_document` сохраняет
прежний контракт «весь документ или ошибка». Preview вызывает его алгоритм
покарточно, сохраняя исходный индекс: `converted`
или `unrepresentable` (V2 валиден, legacy исказит содержимое).
Статус unrepresentable не является ошибкой валидации V2 и не скрывает соседние карточки.
Состояние V2-preview не передаётся в публикацию/обновление TXT/MD.

Проверки без БД и внешних API:

```powershell
venv/Scripts/python.exe -m unittest scripts.tests.test_structured_preview -v
npx --no-install playwright test scripts/tests/browser/structured-preview.spec.cjs --workers=1
```

Браузерная проверка использует фактический preview-эндпоинт на изолированном
сервере `scripts/tests/structured_preview_server.py` (порт 8051), без подключения
к БД и write-роутов. Проверяются XSS, mixed-документ, ошибки, повторная загрузка,
loading/network error и ширины 320/375/430/768/1440px. Скриншоты — в `test-results/`.


## Этап 3: Match → legacy

Тот же `structured_cards_legacy.py` преобразует Match в `::exercise`, затем
`@match` отдельной строкой и строки `left => right` в исходном порядке.
BACK — те же строки пар без директивы; CONTEXT — исходное объяснение.
Информационные блоки, паспорт, наследование уровня/тем, metadata и авторский
`source_id` обрабатываются общим конвертером. Формат V2 не меняется.

Пары не сортируются, не склеиваются и не удаляются: даже одинаковые пары имеют
отдельные позиции. Парсер задаёт `id` по позиции; evaluator сравнивает правые
значения с нормализацией пробелов (без изменения регистра). Поэтому одинаковые
правые подписи, включая различия только в числе внутренних пробелов/табуляциях,
взаимозаменяемы; каждый физический элемент по-прежнему используется один раз.
Сам конвертер внутренние пробелы/табуляции не нормализует.

Поддерживается консервативное подмножество безопасных подписей. Отказ с путём
`cards[i].data.pairs[j].left/right` возвращается для переносов CR/LF,
разделителей `=>`, `->`, `—`, `=`, крайних пробельных символов (включая BOM),
символов Markdown `*`, `_`, обратной кавычки и тегов `<center>`/`<large>`
(включая закрывающие). Парсер не поддерживает надёжного экранирования этих
конструкций; конвертер их не удаляет и не заменяет. V2 при этом остаётся валидным.
Остальные общие проверки конвертера также действуют, например проверка
информационных границ и тем с запятыми.

В «Авторе» Match показывает legacy-проекцию вместе с остальными поддержанными
типами. Непредставимая подпись даёт `unrepresentable`, сохраняет V2-preview
и не скрывает соседние карточки. Сохранения/публикации/миграций нет.
Браузерная регрессия проверяет раскрытую проекцию на 1440/375px и безопасное
отображение отказа для пользовательского HTML.


## Этап 4: Puzzle и Quiz → legacy

Обе ветки добавлены в тот же `structured_cards_legacy.py`; V2-контракт,
учебные компоненты и правила проверки не изменены. Общие информационные блоки,
объяснение, наследование уровня/тем, metadata и авторский `source_id` сохраняются.

**Puzzle:** FRONT содержит `::exercise`, затем `@puzzle` и токены через один
пробел; BACK содержит перевод в точности, включая пустую строку, пробелы,
Markdown или переносы перевода. Исходные токены не сортируются и не склеиваются:
повторы и пунктуация сохраняют позиции. Действующий `StudyCardPuzzle` разбивает
очищенный текст по пробельным символам, создаёт ID по исходным позициям и
использует `puzzleEvaluation.js`; перестановка одинаковых по тексту токенов
по-прежнему ошибочна. Одно слово также поддерживается.

Отказ с путём `cards[i].data.tokens[j]` возвращается для токена с пробельным
символом (включая NBSP/BOM), Markdown `*`, `_`, обратной кавычкой, тегами
`<center>`/`<large>` или отдельным структурным маркером legacy. Это консервативное
подмножество, которое текущий renderer может восстановить без изменения границ
или текста; экранирование и нормализация токенов не добавляются.

**Quiz:** FRONT содержит вопрос, пустую строку и варианты в исходном порядке:
`[*] text` для единственного правильного и `[ ] text` для остальных.
BACK — текст правильного варианта; CONTEXT — исходное объяснение. Идентичность
вариантов сохраняется индексами, а их перемешивание остаётся работой существующего
`quizParser.js`. Адаптер требует ровно один `correct: true`. Несколько правильных
ответов дают `LegacyConversionError` по `cards[i].data.options`, а в «Авторе» —
`unrepresentable`, не ошибку V2. Все исходные правильные ответы остаются видимыми.

Поддерживается вопрос с одиночными переводами строк и однострочные варианты.
Пустые строки внутри вопроса, CR и Unicode line/paragraph separators, крайние
пробелы/BOM, Markdown/control markup,
Trainer-конструкции, отдельные структурные маркеры и пробелы перед `?!.,;:`
отклоняются с путём вопроса/варианта. Также отклоняются префиксы вариантов,
которые текущий parser удаляет (например `-`, `•`, `A)` или `1.`).
Никакие значения не очищаются молча; механика single-choice Quiz не меняется.

Проверки `tools/structured_cards_v2_compat.mjs` используют действующие
`quizParser.js`, `quizEvaluation.js`, `puzzleEvaluation.js` и текущую токенизацию
Puzzle. Сравниваются точные токены/порядок/повторы, перевод, вопрос, варианты,
индексы и правильность каждого варианта. Проверяются все позиции правильного
ответа, неполный/чужой порядок и обмен одинаковых токенов.
Браузерная регрессия дополнительно монтирует настоящие `StudyCardPuzzle` и
`StudyCardQuiz` с проекциями, полученными upload-эндпоинтом: неправильная попытка,
повтор, успешное завершение, перевод, отказ для multi-answer Quiz. Preview
визуально проверяется на 1440/375px. Все данные изолированы от БД и сохранения.


## Этап 5: Word Bank и Free Text → legacy

Все восемь веток находятся в единственном `structured_cards_legacy.py`.
Preview «Автора» вызывает `to_legacy_card` для каждого типа: `converted` либо
`unrepresentable` с путём поля. Отдельного списка неподдерживаемых типов нет.
V2, учебные компоненты, БД, синхронизация и существующие карточки не изменены.

**Word Bank:** FRONT — `@wordbank`, текст с `<<N>>`, затем `@options` и варианты
через ` | `. Номер N равен индексу правильного элемента банка + 1; BACK содержит
`N=исходный вариант` в порядке пропусков. Порядок вариантов, пробелы внутри
строк, переносы LF, Markdown, дистракторы и пояснение сохраняются. Пропуски могут
быть соседними или внутри слова. Две одинаковые строки остаются двумя элементами
с разными `option-N` ID. Как и в действующем механизме, одинаковые по тексту
копии взаимозаменяемы, каждая расходуется один раз; V2-индекс не вводит новую
проверку идентичности одинаковых ответов.

Отказ с `data.options[i]`: крайние пробелы/BOM, CR/LF/Unicode line separators,
разделитель `|`, отдельный структурный маркер. Если нормализация Word Bank
(trim, схлопывание пробелов, lowercase) делает отличающуюся подпись равной
используемому правильному варианту, адаптер также отказывает: дистрактор не
становится правильным молча. Идентичные копии разрешены.
Отказ с `data.parts[i].text`: крайние пробелы всего текста, CR/Unicode line
separators, пустые строки, которые parser схлопывает, литеральные `<<`, `>>`,
`[[`, `]]`, служебный `___WORD_BANK_GAP_` и отдельные структурные директивы
(включая `@options`). Проверяется собранный текст, в том числе маркеры на стыках
соседних text-частей. Конвертер ничего не нормализует и не экранирует.

**Free Text:** FRONT — `@free` и задание, BACK — точный `sample_answer`,
CONTEXT — объяснение. `accepted_answers` и полный `grading_policy` копируются
в **производный** metadata, откуда их уже читает `load_answer_context`.
Это не второй источник V2: metadata исходной V2-карточки по-прежнему не может
содержать поля ответов/оценки. Явно передаются и значения по умолчанию:
V2 без политики означает open_text, тогда как legacy без metadata означает
controlled_text. Нельзя удалять эти поля при дальнейшей передаче проекции.

Действующий механизм поддерживает все текущие поля GradingPolicy: mode
(exact/controlled_text/open_text), typo_tolerance, semantic_equivalence,
grammar_requires_retry, case_sensitive, punctuation_sensitive, max_retries.
Образец и accepted_answers становятся `expected_answers`; совпадение с любым
вариантом проверяется детерминированно. В exact несовпадение отклоняется;
controlled_text допускает безопасные опечатки по действующим правилам;
open_text передаёт несовпадения AI. Семантика/грамматика используют существующий
AI fallback и его проверки policy, число попыток — существующее frontend state.
При отсутствии AI несовпадение в open/controlled может вернуть unavailable,
не засчитывая попытку. Это прежнее поведение, не обещание офлайн-семантической оценки.
Существующая KI-политика может отключать допуск опечаток для spelling/punctuation.

Задание отклоняется с `data.prompt`, если trim/Markdown/control markup либо
структурные границы меняют его текст. Крайние пробелы/BOM образца отклоняются
с `data.sample_answer`, поскольку frontend parser их удаляет. Внутренние
переносы/Markdown образца и accepted_answers сохраняются; варианты не склеиваются.
Непредставимое содержимое даёт unrepresentable; настройки оценки не отбрасываются.
Новых режимов или самостоятельного evaluator у адаптера нет.
